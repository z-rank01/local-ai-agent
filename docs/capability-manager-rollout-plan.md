# 能力管理侧边栏与 A 能力栏 · 落地计划

> 这份文档负责“怎么交付”。设计尺寸、组件解剖和交互规范仍以 [`capability-bar-a-final.md`](./capability-bar-a-final.md) 为准；本文件负责任务拆分、数据迁移、依赖、灰度、回滚与发布门槛。

## 0. 计划结论

| 项目 | 结论 |
| --- | --- |
| 交付目标 | 能力管理侧边栏与 Composer A 能力栏共享一套状态，消除重复卡片与双开关 |
| 交付方式 | feature flag 控制，先内部、再试点、后全量 |
| 设计输入 | `capability-manager.html`、`capability-bar-review.html` |
| 规范输入 | `docs/capability-bar-a-final.md` |
| 粗估工作量 | 约 7.5 人日，含前后端联调；不含设计评审与等待时间 |
| 关键路径 | 状态审计 → store → 侧边栏 → 选择器 → 同步 → QA → 灰度 |
| 发布前提 | `enabled` / `selected` 只有一个数据源；P0 验收全部通过 |

### 0.1 完成定义

- 侧边栏负责“能力管理”，Composer 负责“本轮选择”，两处不再出现同一张管理卡片。
- 侧边栏使用 Switch 表示 `enabled`；Composer 使用勾选/选中行表示 `selected`。
- 停止启用一个已选能力时，当前对话同步移除，并提供撤销。
- 两个面无需刷新即可同步；刷新页面后任务选择可恢复。
- 320 / 768 / 1440 宽度下无横向滚动、无遮挡、无布局跳动。
- 键盘可完成“打开管理 → 搜索 → 启停 → 回到对话 → 选择 → 移除”全流程。
- feature flag 关闭时，旧入口仍可工作；数据不被破坏。

## 1. 范围与假设

### 1.1 本次范围

- `enabled`、`selected`、`available` 三层状态的定义与数据迁移。
- 侧边栏能力管理列表：搜索、类型筛选、启停、导入入口、刷新、空/错误状态。
- Composer A 能力栏：已选胶囊、唯一入口、紧凑选择行、管理入口。
- 两个面的实时同步、移除后的撤销、请求失败回滚。
- 可访问性、响应式、埋点、feature flag、灰度与回滚。
- 设计稿与工程实现的视觉验收。

### 1.2 非范围

- 技能/插件市场、推荐排序、AI 推荐。
- 编辑能力内部参数、编写/发布新能力。
- 批量导入、复杂冲突合并、跨工作区共享。
- 拖拽排序与已移除历史的完整交互；如需要，另立小项目，不在本次强行塞回卡片。
- 新的权限模型；沿用现有工作区权限。

### 1.3 计划假设

- 现有注册表已有稳定 `id`、`name`、`kind`、`description`、`icon`。
- 任务状态可新增/读取 `selectedCapabilityIds`，无需大规模后端重构。
- 现有导入与刷新接口可复用；本计划只改 UI 和状态接线。
- 设计系统 token 已在目标应用加载，不需要新增色板。
- 1 名前端为主，平台/后端与 QA 按阶段介入。

> 如果数据模型或接口不满足以上假设，先做技术 spike，不要直接进入 UI 开发。

## 2. 目标架构

### 2.1 三层状态

```text
enabled     工作区级：能力是否允许被任务选择
selected    会话级：当前任务是否挂载该能力
available   derived：enabled && status === 'ready'
```

### 2.2 两个面

| 面 | 角色 | 数据范围 | 控件 | 状态词 |
| --- | --- | --- | --- | --- |
| 侧边栏 | 能力管理 | 全部，含停用/不可用/历史 | Switch | 已启用 / 已停用 |
| Composer | 本轮选择 | 仅 enabled 且 available | Check / 选中行 | 本轮已选 / 未选 |

### 2.3 单一数据源

```ts
interface CapabilityState {
  registry: Map<string, CapabilityItem>;
  enabledIds: Set<string>;
  selectedByConversation: Record<string, string[]>;
}
```

- 组件内部只保留浮层开关、搜索词、焦点等瞬时 UI 状态。
- 侧边栏和 Composer 都从同一 selector 派生，禁止各自请求后维护本地数组。
- `selected` 只存 id，不存整份能力对象，避免 registry 更新后两份数据不一致。
- 侧边栏切换 `enabled` 后，Composer 的 `available` 列表与已选胶囊即时更新。

### 2.4 关键交互决定

| 场景 | 行为 |
| --- | --- |
| 侧边栏停用一个已选能力 | 从当前对话移除，toast 提供撤销 |
| 能力正在运行 | 当前运行允许完成，下一次不可选 |
| 删除/卸载能力 | 从所有任务选择中移除，保留撤销提示 |
| 导入能力 | 复用现有导入策略；若默认启用，Composer 立即出现 |
| 同一能力重复添加 | 按 id 去重，no-op |
| 请求失败 | 回滚乐观更新；两部分状态一致 |

## 5. 数据迁移与灰度

### 5.1 迁移步骤

1. **盘点旧字段**：确认旧 `active` / `enabled` / `selected` 的真实语义，不要假设同名即同义。
2. **建立映射**：旧全局开关迁移到 `enabledIds`；旧任务选择迁移到 `selectedByConversation`。
3. **双读阶段**：新 UI 读新字段，必要时回退读旧字段；写入只写新字段。
4. **双写阶段**：短期同步旧字段，保证 flag 关闭时旧入口仍可用。
5. **验证**：用真实任务验证选择恢复、停用移除、刷新、跨设备。
6. **收敛**：稳定一个版本后停止双写，再移除旧字段。
7. **清理**：删除旧入口与兼容代码，保留一个版本的只读回滚能力。

> 如果旧字段语义无法确认，先停下来问产品/平台，不要用“两边取并集”掩盖数据问题。

### 5.2 Feature flag

建议开关：`workbench.capabilities.v2`。

- 关闭：旧侧边栏与旧 Composer 入口保持原样。
- 打开：侧边栏使用管理列表，Composer 使用 A 能力栏与紧凑选择器。
- 两个面必须由**同一个 flag**控制，避免只切换一半导致状态错位。
- 灰度顺序：开发环境 → 内部账号 → 1 个试点工作区 → 小范围项目 → 全量。
- 回滚：关闭 flag 即可；数据保留，新字段不被清空。

### 5.3 回滚策略

- **一级回滚**：关闭 flag，切回旧 UI；新字段保留，旧字段仍可读。
- **二级回滚**：若旧 UI 无法读取新字段，启用双读适配器，不做破坏性回写。
- **三级回滚**：仅在新字段写坏时使用备份恢复；必须保留操作日志。
- 回滚后不要删除新字段，至少保留一个发布周期。

## 6. 验收与测试

### 6.1 发布门槛

- [ ] 侧边栏与 Composer 共用同一份 `enabled` / `selected` 状态。
- [ ] 侧边栏只有 Switch，Composer 只有勾选/选中行；没有双开关。
- [ ] 停用已选能力时，Composer 即时移除并出现撤销。
- [ ] 搜索/筛选后启停不会丢失当前任务选择。
- [ ] 320px 下无横向滚动、无文字遮挡；1440px 下不出现过度拉伸。
- [ ] 键盘可完成管理 → 选择 → 移除 → 关闭全流程。
- [ ] 屏幕阅读器能读出开关状态、对话中状态和操作结果。
- [ ] 关闭 localStorage / 请求失败时，界面可用，已有选择不丢失。
- [ ] 刷新后任务选择恢复；新任务为空。
- [ ] 导入/刷新失败有错误反馈，不出现半成功状态。
- [ ] 埋点不包含完整搜索词或用户输入原文。
- [ ] flag 关闭可回退，旧入口仍可读取选择。

### 6.2 测试矩阵

| --- | --- | --- | --- | --- | --- |

补充：200% 缩放、系统字体放大、触屏粗指针、慢网、双面同时打开、切换任务、能力正在运行。

### 6.3 视觉回归重点

- 行高不因长描述或状态徽标变化而跳动。
- 开关与行尾对齐，不覆盖标题或错误标记。
- 分隔线起点与图标列对齐。
- 侧边栏滚动时表头、搜索、筛选保持稳定。
- Composer 浮层不被裁剪，关闭后焦点回到触发器。
- 暗色面板文字对比度 ≥ 4.5:1，焦点环可见。

## 7. 风险与应对

| 风险 | 级别 | 影响 | 应对 | 负责 |
| --- | --- | --- | --- | --- |
| `enabled` 与 `selected` 语义仍混用 | P0 | 双开关、状态错乱 | D1 先审计；无法确认则暂停 UI 开发 | FE + 平台 |
| 两套本地 state 残留 | P0 | 两面不同步 | 删旧 store；统一 selector；代码审查检查 | FE |
| 停用已选能力未清理 | P1 | 运行使用已停用能力 | S1 覆盖；toast + 撤销；发布前专项测试 | FE |
| 侧边栏列表被容器裁剪 | P1 | 内容不可达 | 检查 overflow；必要时 portal/滚动容器 | FE |
| 迁移丢选择 | P0 | 用户上下文丢失 | dual-read、备份、灰度前对账 | 平台 |
| 搜索/请求竞态 | P1 | 结果错乱 | 只接受最后一次请求；取消旧请求 | FE |
| 焦点在重渲染后丢失 | P1 | 键盘不可用 | 行级 refocus；A1 回归 | FE |
| 导入只完成 UI | P2 | 用户以为已导入 | 明确“等待解析”；错误态；不要伪造成功 | FE + PM |
| 旧入口提前删除 | P1 | 无法回滚 | 保留一个版本；flag 关闭路径可读 | PM |

### 7.1 停止发布条件

出现以下任一情况，不进入全量：

- 两个面读取不同状态。
- 停用已选能力后仍能被下一轮运行使用。
- 迁移造成已有任务选择丢失。
- 320px 出现横向滚动或操作按钮被遮挡。
- 键盘无法关闭浮层或焦点进入隐藏区域。
- flag 关闭后旧入口不可用。

## 8. 埋点与观察

| 事件 | 时机 | 关键字段 |
| --- | --- | --- |
| `capability_manager_open` | 打开侧边栏能力区 | `surface`, `entry` |
| `capability_enable` | 启用能力 | `id`, `kind`, `source` |
| `capability_disable` | 停用能力 | `id`, `kind`, `was_selected` |
| `capability_context_remove` | 从对话移除 | `id`, `reason` |
| `capability_search` | 搜索停顿 | `query_length`, `result_count` |
| `capability_filter` | 切换筛选 | `kind` |
| `capability_import` | 导入入口 | `result` |
| `capability_refresh` | 刷新 | `result` |
| `capability_empty` | 空结果 | `query_length`, `kind` |
| `capability_sync_error` | 双面同步失败 | `stage`, `error_code` |

原则：

- 不上报完整搜索词和用户输入原文。
- `was_selected` 用于验证“停用已选能力”的路径，不做用户画像。
- 观察重点是错误率、状态不一致、空结果和回滚次数，不设拍脑袋的增长指标。
