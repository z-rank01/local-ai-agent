# 金融研究 Recipe 与材料交接契约

新建研究使用 `research_contract_version=3` 与 `Recipe.schema_version=3`。源码、部署、内容验收分别记录；当前进度只看股票仓库 `docs/计划.md`。v2 保留历史读取和兼容，不作为另一条新研究路径；旧研究不改写，不自动恢复旧任务或 UNKNOWN。

独立核对只使用核对角色系统指令，不继承作者的研究启动、工具编排及写稿发布指令；同一冻结模型、方法正文、原问题和实际材料仍然保留。作者按原问题及Recipe目标判断补查、收窄或发布，核对意见不会自动扩展用户要求；建议式模式不要求意见清零。

## 状态与上下文

子Agent扩展沿当前回合策略提供通用接口；金融材料投影、web_fetch来源保存、角色成果登记和结果摘要归金融插件。Harness仅调度并保存真实回执，角色使用同一登记输出契约。作者的task不重定义输出格式；evidence_ids仅指本轮授权的task_evidence，依赖成果由系统交接，不能用source_id或artifact_ref代填。

角色最终source_excerpts成果与工具读取source_excerpts回执分层处理。下载保存的全文不等于模型已读；读取脚本须实际返回完整JSON回执，并以来源指纹、页码、字符范围和原句核验。将最终artifacts草稿或同一JSON的若干字符串切片打印出来，不会登记为原文读取。角色成果中的未登记来源、空引句或未匹配引句逐项保存validation_errors，带原索引及摘录ID交给作者和依赖角色；有效摘录仍可采用，原始成果及失败记录不修改，不因角色COMPLETE宣称全部摘录通过。

唯一完整JSON代码围栏可确定性读取；围栏前后说明随原始可见输出保留在raw_text，不当作结构化成果。多块围栏不猜选，裸JSON外夹说明不猜取，缺字段、非法JSON或截断仍失败；不额外调用模型修格式。父运行退出先等待子角色收尾，已执行且无确认回执保留UNKNOWN；历史批次只读，不自动重启。供应商stop与本地交付状态独立记录，空正文和解析失败不能变成COMPLETE；正文字符数与终态标志只作诊断，不保存隐藏推理。

| --- | --- |
| 唯一研究状态 | Recipe 随原研究状态进入原运行检查点；`research.json.recipe` 是工作区投影。旧版本留在 `recipe_history`，原始材料不另建副本库 |
| 写作者交接 | v3收到新核对反馈时建立recipe-author-v3输入包（历史v2保持原版本）：原问题、Recipe、全部已返回证据、实际角色成果、所选方法、最近提交稿及最新核对意见；其后全部连续操作继续进入请求，包括另存新稿、脚本参数与回执，不每步重置为两条消息。新一版核对再建立边界；边界无法定位时保留原视图。完整可见历史另存原task_evidence并可回读 |
| 核对交接 | 当前稿、同版证据、方法、Recipe、已知冲突与历史问题；作者自查肯定不进入独立核对视图。claim_provenance只记录原句及引文能否在当前稿/实际返回资料中定位；模型assessment和观察日期仍是模型标注，引用匹配不认证语义，不增加发布否决权 |
| 请求材料清单 | 从建立研究之前首次工具流请求起，供应商完成消息序列化后归档可见协议，关联实际调用 ID、消息指纹、证据 ID 和原文范围。初始清单可跨原检查点保留；记录完整材料是否在本次请求中，不以保存或下载状态冒充已纳入请求 |
| 安全与隔离 | 沿用当前会话、工作区和云读授权；归档不保存隐藏思维链、认证头或密钥，不授予新权限 |

重要判断在阶段 `claims` 中关联主体、指标、期间、单位与 `evidence_refs`，引用实际 artifacts。原文数值、原文含义和作者推断分开；程序只验证可验证的引用与计算，不认证金融语义。表头、单位和期间不得用孤立数字替代。

新研究自主选择是否使用方法，不以目录发现、方法读取或阶段完成数量解锁工具或发布。选用时仍沿本轮固定版本读取并交接正文。方法为空不代表来源已足够，公开原文与引用、算式及权限仍按真实状态校验。

“已保存”“工具已返回”“纳入本次请求”是不同状态；纳入请求也不等于正确理解。Recipe v2不走旧工具批次预览，避免源文仍在但脚本操作和新文件选择被压成索引；旧契约保留原解释。历史大工具回执仍可通过 `context_evidence_read` 回读，材料清单显式记录完整材料未纳入的情况。

## 发布与运行边界

分红证据分列所属盈利期与宣告/实施状态、实际付款主体/时间/金额、相同主体和期间的现金收支与可动用资金。可分配利润是会计额度，派现/经营现金流比率是规模参照，两者都不证明实际支付来源；覆盖下降不证明依赖存量现金，覆盖充足也不证明未使用存量现金。证据链不足时保留来源未知，相关补查记入Recipe未解问题。作者和核对者都按此区分，不把核对建议改写成相反的确定事实。

研究截止日与抓取时间分开。事后行情或新披露如需呈现须单列，不作为截止日可知估值、趋势或风险判断的依据；缺少匹配时点行情时保留估值未知。这是金融分析与核对的方法边界，不隐藏工具、不认证事实、不增加强制发布门槛。

新契约的发布必须关联当前稿与当前证据的反馈；`review_response` 是可见的简短处置说明，不是隐藏推理，也不是逐条终审表。核对建议可错，作者可不采纳；`PUBLISH_REVIEW_ENFORCE=false` 保持建议式。

暂停、停止、权限撤销、退出与保存失败仍保留真实结果；核对 UNKNOWN 不发布、不自动重发。契约代码和提示进入既有兼容指纹；不兼容的检查点拒绝原地续行，用户可沿原入口建立关联新运行。

核对记录同时保存程序收到的原生终态、finish_reason、用量计数及调用标识，不保存隐藏推理。输出length截断记录为TRUNCATED，不冒充已完成核对、网络UNKNOWN或研究预算耗尽，也不自动重发。

对目录中已核实支持json_object的型号，单独核对派生JSON输出请求；普通聊天、取证和写作不继承该格式，不改变模型或思考参数。能力声明随模型快照冻结，实际response_format沿核对请求回执保存；未知能力不猜测，显式冲突参数不覆盖。JSON模式仍可能返回空白或不合法结构，此时保留原响应及真实失败，不自动重发、修补事实或发布。JSON语法错误另记类型、行列与字符位置，区别于原生模型调用失败。

模型目录保留供应商对该模型声明的上下文与最大输出容量。已有显式输出配置优先；无显式配置时使用已声明容量，未知时保留供应商默认。实际输出参数随本轮、检查点和股票execution_profile冻结，目录或全局配置刷新不修改在途请求。缺少输出参数快照的旧云端检查点/任务明确拒绝原地续行，保留原记录。此项不切换模型、不改变思考强度、不增加研究累计限制。

作者交接的可选工作稿刷新遇到传输错误时，保存一次author_candidate_refresh失败回执，current_candidate标READ_FAILED；此前快照单列previous_snapshot，不能标成本次已读。请求材料清单将未知版本的当前稿列为未纳入，旧快照另列实际范围。模型可通过原工具选择检查，不内部循环重读、不重发模型调用；权限拒绝和检查点保存失败继续抛出原错误。成功回读后使用新实际指纹，原失败回执保留。

工具已返回的真实结果先沿原协议归档。后续研究投影或检查点保存失败时，宿主保留该回执及执行状态，单列收尾未完成；不为同一调用追加泛化的中断协议，不将已知参数错误或已返回成果覆盖为未知。运行仍按实际保存错误失败，不能因此取得安全检查点或自动重发。尚未收到回执的步骤继续保留中断或未知状态。

研究不受累计时长、轮数、工具调用次数或无进展计数强制收尾。后台研究仍由任务需要选择。原 broker v1/v2、账户确认、业务准入及单次网络超时保持原义。不新增数据库、执行器、设置入口或 Recipe 编辑器。

部署仍为根目录 `启动.bat` 对应的唯一启动器；镜像资源与工具定义变更使用 `-Build`。参见[架构图](./finance-recipe-architecture.html)与[本批记录](./记录/2026-10-30-IN4.19-Recipe闭环与最终验收.md)。

### 成果适用版本与显式换算

作者与核对输入中的阶段和claim均带程序投影outcome_version。采用候选稿的正文指纹与当前稿不一致或无法核实时标OLDER_OR_UNVERIFIED_CANDIDATE；只读旧评估不自动变为当前结论。模型通过原stage_updates更新判断及采用的新candidate引用，历史记录保留；CURRENT_TEXT_REFERENCE仅代表正文引用匹配，不认证计算或金融语义。无候选引用标UNBOUND，不隐藏工具、不强制补表。实际校验后的候选及计算同时登记到原artifacts。

显式货币换算的除法系数单位须为输入单位/输出单位，乘法相反，系数数值须与货币单位尺度一致；错误返回calculations索引，不修改原稿。

### 交接投影与反馈范围

作者交接保留实际原文与可回执回读的完整历史，但反馈工具结果不重复携带已由materials/latest_feedback提供的Recipe、artifacts和review；历史计算artifacts仅为索引进项保留摘要，被claims采用的算式保持完整。语义Recipe投影排除execution与active_stage_id，原始research.json及工具回执不改写。previous_findings仅保留core_answer，optional与postpublication留在本次反馈，不自动扩展下一轮任务。

### 跨模型结构化请求（2026-11-04）

无工具角色和独立核对共用冻结模型的 `structured_output` 能力。已确认型号由模型适配层派生请求：兼容云接口使用 `response_format={"type":"json_object"}`，本地 Ollama 使用 `format="json"`。金融 RoleSpec、Recipe、必需字段及引用校验保持一致；工具角色和作者正常使用工具协议。未知型号使用普通请求并严格校验，不能保证成功。

本次新增登记 `qwen:qwen3.8-max`、`ollama:qwen3.8:27b`；DeepSeek 保留原登记。依据分别为[阿里云文档](https://www.alibabacloud.com/help/en/model-studio/qwen-structured-output)和[Ollama 文档](https://docs.ollama.com/capabilities/structured-outputs)，本机 Ollama 0.34.4 已安装该 Qwen。思考设置、模型默认选择及输出额度不随格式派生改变，显式格式冲突拒绝覆盖。冻结声明适用于聊天、子角色及检查点读取；旧快照不会因为目录新增能力而改变请求。实际格式参数进入原生回执与核对记录；非法 JSON、空响应和缺失字段仍真实失败，不修补事实或自动重发。

### 请求清单与成果引用（2026-11-04）

实际序列化材料的完整范围清单归档到原 task_evidence；research.json 的 request_materials 只保存 manifest_ref、请求身份、消息证据索引与材料数量。引用登记在同一父运行授权证据集合内，完整清单可沿 context_evidence_read 分页回读；归档失败明确失败，不保存假引用。无归档器的历史兼容调用保留内嵌清单，既有失败文件不改写，10 MiB 文件策略不放宽。

作者和独立核对共用 artifacts 字典；claim_materials 只导航到对应 ref，不逐条复制成果正文。claims 的条件、反证、未知、原始产物与采用的计算保持原样。核对字典同时包含非角色产物，避免引用化后丢失候选计算等材料；缺失引用仍明确标记，导航不认证内容。

本地工具流与云端流均记录原生结束状态、可见正文长度、终态、用量及交付状态；首末数据块时间与网络失败阶段只作诊断。Ollama HTTP 错误在关闭响应前读取并只保存固定错误分类，不存供应商自由文本或隐藏推理。缺终态、损坏流、服务端错误和 length 不冒充完成，不自动重试、换模型或调整思考及超时。

### 开发时离线回放角色结果

在仓库根目录运行 `.\.conda\python.exe -m tests.finance_recipe_replay <工作区ID> <研究ID>`。可用 `--batch`、`--role` 单选，用 `--show-artifacts` 在本机查看通过解析的公开产物。此模块只在 tests 中，由开发者显式执行，不注册 API、工具或运行时开关。

回放从原库按会话、工作区、批次及角色定位 result_ref，使用当前登记角色与生产解析器，分列原状态、当前解析结果、已存映射错误及核对与作者决定的对应关系。无确认输出单列；不会调用模型、更新研究或发布。产物哈希相同只能证明解析得到同一内容。依赖实际收到的请求、财务原件核实及页面行为仍须分别检查。

`--stage` 支持 evidence、calculation、analysis、role_review、author、review、publication、followup。角色材料的 prepared_input 是角色调用前归档的交接包；serialized_requests 单列可用实际尝试编号关联的传输清单。evidence 核验登记原件哈希和页内字符位置；followup 列出同会话后续运行检查点引用的历史索引。业务结论仍须阅读原件。

单阶段命令为 `.\.conda\python.exe -m tests.finance_recipe_probe <工作区ID> <研究ID> <原运行ID> <核对尝试ID> --stage review --change "本次要测试的提示修改"`。默认仅验证材料，增加 `--live` 才调用一次冻结的 DeepSeek，沿原模型账本登记新调用。仅支持能核实原云读授权、逐条消息哈希、已发布运行绑定及模型参数的无工具核对样本。没有可验证的角色序列化输入或原工具声明时采用离线测试。单次核对仍可能携带完整候选稿和材料，应按回执统计实际用量。

无工具子角色使用相同命令，将尝试 ID 选为原模型账本的 ledger_call_id，并指定 `--stage analysis` 或 `--stage role_review` 与 `--batch <批次ID>`。工具从 role_prompt 和原材料重建消息后验证模型账本的 input_hash 与 execution_hash。旧版本角色提示变化导致哈希不匹配时，在新调用前停止。分析与角色审查均在万德斯正式修订样本上取得哈希匹配。带工具的取证、计算以及作者的原工具声明未能从这些历史档案完整核实，使用离线回放。

### 新研究的差异复核

delta-v1 只在新建研究时冻结。首稿完整核对，编辑工作文件可以连续进行，下一次送审与本研究上次成功核对的冻结候选比较。局部核对保留原问题、截止日、核心结论及改动前后内容。限制或反证也是核对内容。正文、数字及核心主张变化时扩大材料，无法对应、来源或期间变化时做完整核对。已收到的数字引文邻文供核实表头，替代解释须给出表名、行列与期间，位置不足标为待核实。

原 reviews 结果保存父稿、稿件与依据指纹、范围、实际材料引用和未结意见。仅内部自查或编制备注改变时，记录沿用的回执，实际模型调用次数为零。发布必须携带当前稿的 review_ref 和作者自己的 review_response。UNKNOWN、失败或截断沿原规则收尾。

开发者使用 python -m tests.finance_recipe_replay <工作区ID> <研究ID> --stage review。revision_replay 将历史原生用量与离线生成的用户消息字符数分别展示。缺少已验证的原调用材料时显示 unconfirmed。表格邻文根据来源哈希匹配后从归档的已接收文本重建。

### 自然问题与方法材料
