# N2 日常运行与验收

更新：2026-09-14。本批实现恢复执行、股票服务启停与 Web 人工控制；跨仓库进度仍以股票仓库 `docs/计划.md` 为准。后续顺序为 IN4.16 → IN4.18 → 其他 IN4。

## 日常入口

首次已安装 Python、Node 和 Docker 依赖后，在 local-ai-agent 根目录运行：

```powershell
.\scripts\start-daily.ps1
```

打开 `http://127.0.0.1:5173`。脚本启动工具容器、BFF 与 Web；不强制要求 Ollama。模型仍由 Web 模型选择和既有配置决定。仅检查聊天/控制界面可使用 `-SkipTools`，文件/Python 等容器工具需另外启动；此参数不代表容器工具可用。

若 9510 正被旧 IN1 启动模式占用，脚本会明确停止启动流程；先完成旧研究的收尾并退出旧 Web/BFF，再启动日常入口。脚本不会按端口杀掉现有进程。日常工作区是 `.env` 配置的工作区（本机 `data/workspace`），不是 IN1 的 `data/in1/workspace`；IN1 对话仍在旧库，本批不迁移或删除历史。

右侧栏向下滚动到“股票服务”，展开“连接配置（首次设置）”：

| 项目 | 日常设置 | 独立验收设置示例 |
| --- | --- | --- |
| 股票仓库路径 | `D:\Stock_Agent_Workspace` | 相同 |
| 状态目录 | `simulation` | `data/n2-acceptance-01` |
| 端口 | `8765` | `18765`（先确认未占用） |

路径是本机示例，可换安装位置；状态目录必须在选定股票仓库内。保存后点击“开启股票后台”。配置、后台开关和 worker 开关保存在聊天侧 `data/private/daily-services.json`，下次脚本启动恢复这些选择。凭据由股票侧生成，仅在本机服务端读取，不放入对话或模型工具参数。

## 三种日常用法

1. **只聊天**：股票后台保持关闭，股票工具不进入工具目录；聊天、文件与通用工具独立使用。
2. **股票后台开启，任务执行暂停**：可以查看账户和已有研究。排队任务不执行；暂停不会取消已存在的任务。需要运行时点击“开启任务执行”。
3. **任务执行开启**：先检查业务模式。恢复模式只执行恢复核对，不机械重放旧候选研究；正常模式执行原有日任务、研究和预算规则。开启 worker 不等于立即允许新的业务操作。

“暂停任务执行”停止领取下一任务，当前任务继续收尾；界面显示“正在收尾”时等待即可。“关闭股票后台”会先暂停，未收尾时给出明确提示，稍后再点击；关闭股票后台不关闭聊天。退出整个应用也必须先完成股票任务收尾。再次使用整个应用时运行启动脚本。

后台停机或 worker 暂停多日后重新开启，都会重新检查恢复门禁。日历缺失、策略版本变化或历史交易/权益有问题时保留只读，并显示原因，不通过修改 `runtime.mode` 或水位绕过。

## 恢复如何工作

- 持久化一个恢复批次及逐日步骤；默认每批处理最多 3 个交易日，暂停/重启后沿用完成步骤。每个失败步骤最多自动尝试 3 次，间隔 30/60/120 秒；可在修复数据源后手动重试。
- 每日单独记录尝试与完成；只有按顺序核对成功才推进恢复账本水位。普通日任务也不能跨缺口把“今天成功”当成历史全部完成。
- 从历史现金流水、成交和已确认权益重建当日持仓与估值，记录 `RECONSTRUCTED` 和此次取得时间；不把当前持仓回填到过去，也不伪造离线期间已实时监督。
- 历史订单仅按原批准条款核对；若缺历史证券状态，或订单之后已有账本变动，保留阻塞。已有成交和入账凭证通过原唯一键复用。
- 日线与公司行动按日期采集；持仓日的公告另记覆盖结果，当前持仓的复权/财务等资料单独复核。历史资讯、论坛与专业监督不能证明完整的，周期记录保持 `PARTIAL`，并列为待办；不以股价已补齐冒充全部信息完整。
- 周/月/季度分别留存所覆盖区间的账本汇总，未覆盖完整周期不标完整。历史模型请求有可验证的本地成功回执时补回原记录；无回执、无持久化服务端运行标识时保留结果不明，不猜请求 ID，不重发付费请求。本批恢复不生成新的模型调用。
- 恢复前后生成 SQLite 备份；完成后由用户在 Web 核对摘要、点击一次性“确认恢复”。短缺口也采用人工确认的保守默认；新订单仍需原有逐笔确认。

“当前资料缺失”“卡片过期”“模型结果不明”会显示在待办中。复杂权益（配股、税款、已售持仓的迟到权益等）沿用既有明确阻塞，不自动猜测。后台的人工操作区直连可信操作入口，可输入“帮助”“账户”“权益待办”以及其返回的确认指令，内容不经过模型；本批没有放宽既有账本修正权限。

## 推荐人工验收（零模型调用）

先创建一个**全新的独立现金演示账户**，在股票仓库根目录执行：

```powershell
.\.venv-paper\Scripts\python.exe -X utf8 scripts\seed_n2_demo.py --state-dir data/n2-acceptance-01
```

脚本遇到已有数据库会拒绝覆盖。重复验收改用新目录名，不删除或重置旧数据。现金账户没有持仓，因此这段恢复不调用外部数据源或模型。

1. 运行聊天仓库 `scripts/start-daily.ps1`。先保持股票关闭，确认 Web 能正常加载，工具列表中没有股票工具。
2. 在“股票服务”填入上述独立验收设置并保存，开启股票后台。应显示任务执行“已暂停”、业务“恢复核对中”，有 **4 个交易日**待核对；股票查看工具出现。
3. 点击“开启任务执行”。恢复记录应从 **0/4 → 4/4 已完成**，已核对日期推进到最新收盘交易日；此时仍待用户确认。
4. **先点击“暂停任务执行”**，再点击“核对并恢复运行”及“确认恢复”。应变为“正常运行”，任务执行仍暂停。这样不会启动正常日任务或自动候选研究。
5. 展开“逐日恢复记录”，核对四天各有一条完成记录；历史信息不完整的说明仍在，不能被描述为过去已监控。
6. 单击“关闭股票后台”，按钮应立即显示“正在关闭股票后台…”，等待后台退出后自动显示“后台未运行”，无需第二次点击或手动刷新；再等待至少 5 秒，状态不应回跳或出现连接失败。Web 保持可用、股票工具消失。再次开启后，已核对日期、四条恢复记录及 worker 暂停选择应保留，不重复入账。
7. 退出日常 Web/BFF 后再次运行脚本，确认配置和开关选择保留。最终关闭股票后台，再将连接配置切回日常目录 `simulation`；日常库存在真实阻塞时按待办处理，不能套用演示库的通过结果。

研究能力体验属于后续人工验收：日常账户确认可运行并开启 worker 后，提交/查询一项研究，暂停或关闭前观察收尾。此过程可能触发原有日常管线和模型预算；零调用验收不包含该动作。

## 工程验证与边界

验证使用临时数据库、冻结行情和独立 Web 端口，不改日常账本。定向测试覆盖现金缺口、历史持仓、原订单一次入账、迟到资料拒绝、失败退避、暂停、重启接续、日历缺失、策略变化、原模型回执复用、控制凭据隔离和 Web 安全收尾。全量离线测试及 Web 构建结果记录在统一计划本批条目。

本批不替代 IN4 的专业能力扩展，不解决 IN4.17 板块限制或 IN4.18 通用规则拒绝投影；N2 面板直接展示恢复原因，模型工具的通用错误契约仍按 IN4.18 处理。IN4.3 的历史会话跨入口访问、完整切换与回退仍单独验收。
