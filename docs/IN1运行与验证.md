## 2. 已接通的行为

| 编号 | 实现和使用方式 |
| --- | --- |
| IN1.1 | `config/models.json` 定义云端模型；BFF 按选择路由客户端、更新会话模型、记录每条回复来源。刷新恢复会话模型，编辑重发/重生成携带当前选择。401、超时、断流与空回答明确报错，不自动切换供应商。未配置密钥的云端模型在选择器中禁用并提示去"模型设置"；密钥只验证存在性、不做连通性预验。 |
| IN1.2 | SQLite 增量迁移保存完整 assistant/tool 协议，另存用于展示的内容、参数、结果和状态；协议行不出现在 UI 中。历史缺失的工具回执标记中断，避免孤立 tool 消息。 |
| IN1.3 | 单会话运行互斥；Web 请求标识持久去重。工具失败交回模型，模型失败保留已取得内容。停止关闭流并终止执行进程组，保留收到的 stdout/stderr 和中断回执。 |
| IN1.4 | 取消强制"执行/结果"回答格式；文件内容由明确工具调用取得，轨迹可见。云端不自动加载旧本地记忆，云端历史与跨会话查询只取可发送消息。上下文压缩保留完整近期 user/tool 轮次。 |
| IN1.5 | 默认开放 core 与 extended 工具；支持 `code_exec`、`skill_list`、`skill_info`、`skill_register`、`skill_run`。skills 仍是包含字面量 `SKILL_METADATA` 和 `run(params)` 的 Python 文件；元数据发现/校验不在 API 主进程执行技能代码。**技能格式与 Agent Skills 标准尚未对齐，已立项为 `IN4.16`。** |
| IN1.6 | `file_read` 对文本文件按同一次读取返回内容与 SHA-256；xlsx/pdf 走解析分支，哈希取自原始字节、文本由解析器二次读取，因此"同一快照"只对文本分支成立。`file_edit` 只接受唯一原文匹配及当前哈希，原子替换，返回 diff 和新哈希。哈希检测不能替代任意外部进程的事务锁。支持 UTF-8 中文、CRLF、长文件和连续编辑；`file_edit` 对非 UTF-8 明确拒绝且保留原字节，`file_read` 则按 gbk/gb18030/big5/latin-1 等兜底解码。 |
| IN1.7 | `shell_exec` 使用 Linux `/bin/sh`，cwd 限于 `/workspace`，支持搜索、脚本和测试。shell/Python/skill 执行显示进度与增量输出，保存退出码、超时和截断状态。 |

"重新生成"复用该轮已有工具回执，仅重新组织回答，**不会重新运行写入或脚本**；要重新执行请另发明确指令。编辑用户消息会重跑修改后的请求并重写后续历史；**已发生的文件修改不会随聊天版本切换回滚**。

**隔离边界**：通用文件工具受路径保护；执行进程在非 root 容器内，根文件系统只读，工作区/临时目录/包目录可写，有 CPU、内存、PID 限制，不挂载宿主项目、密钥或 Docker socket。**字符串策略只是补充，不能视作 Python/shell 的安全沙箱；容器允许出站网络**，`pip_install` 仍可安装依赖。

**首期不提供**：宿主机 CMD/PowerShell、Bash 保证、交互式 PTY、跨重启进程恢复、`SKILL.md` 方法型技能包。共享本地记忆沿用 Ollama 路径；云端使用会话历史和压缩，不自动把本地共享记忆升级为云端记忆。

## 4. 密钥、数据与调用额度

- 密钥保存在 `data/private/model-keys.json`；该目录被 Git 忽略，也不在执行容器的工作区挂载中。环境变量 `DASHSCOPE_API_KEY` 仍可替代文件配置。
- 授权设置存 `data/private/model-settings.json`。**不同工作区路径独立授权**，刷新和重启后保留；思考开关不改变工具授权，关闭工具不会撤回此前已发送的内容。正在生成时后端拒绝修改，避免半轮切换能力。
- **普通启动默认不授权云端读取工具结果**，需在顶部模型设置显式开启。IN1 启动脚本为隔离测试工作区提供默认授权，但**界面保存的同工作区授权状态优先于启动默认值**，因此用户关闭后重启不会再次自动开启。请只放允许发送给云端的材料。
- 工具可返回 `model_observation` 与 `local_result` / `local_attachments`。模型历史取递归投影，完整本地结果供 UI 展示；后续摘要和跨会话工具也不能回读 UI 原始附件。
- **模型调用上限 120 次**（`scripts/run_in1.py` 的 `MODEL_CALL_LIMIT`）：IN1 用 30，2026-09-07 用户批准 +30 供 IN2 联调，2026-09-08 翻倍至 120 供 IN3 验收（提交 `9563ba7`）。按 **HTTP 请求尝试**计数，工具后的再次推理和压缩也计数；**失败尝试不返还额度**。账本为 `data/in1-model-calls.sqlite`，重启不清零。
- **账本现状（2026-09-10 复核）**：已记录 **93/120** 次，最后一次为 2026-09-09 15:45 UTC（IN3 模型在环复验，见 §7）。人工试聊同样占用剩余次数；如需增加应先明确新额度并调整启动配置，**不能删除账本绕过限额**。
- 普通启动配置的调用上限若为 0，界面显示"不限"，该模式调用不计入本账本。
