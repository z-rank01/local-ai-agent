## 2. 已接通的行为

| 编号 | 实现和使用方式 |
| --- | --- |
| IN1.1 | `config/models.json` 定义云端模型；BFF 按选择路由客户端、更新会话模型、记录每条回复来源。刷新恢复会话模型，编辑重发/重生成携带当前选择。401、超时、断流与空回答明确报错，不自动切换供应商。 |
| IN1.2 | SQLite 增量迁移保存完整 assistant/tool 协议，另存用于展示的内容、参数、结果和状态；协议行不出现在 UI 中。历史缺失的工具回执标记中断，避免孤立 tool 消息。 |
| IN1.3 | 单会话运行互斥；Web 请求标识持久去重。工具失败交回模型，模型失败保留已取得内容。停止关闭流并终止执行进程组，保留收到的 stdout/stderr 和中断回执。 |
| IN1.4 | 取消强制“执行/结果”回答格式；文件内容由明确工具调用取得，轨迹可见。云端不自动加载旧本地记忆，云端历史与跨会话查询只取可发送消息。上下文压缩保留完整近期 user/tool 轮次。 |
| IN1.5 | 默认开放 core 与 extended 工具；支持 `code_exec`、`skill_list`、`skill_info`、`skill_register`、`skill_run`。skills 仍是包含字面量 `SKILL_METADATA` 和 `run(params)` 的 Python 文件，元数据发现/校验不在 API 主进程执行技能代码。 |
| IN1.6 | `file_read` 给出文件同一快照的内容与 SHA-256；`file_edit` 只接受唯一原文匹配及当前哈希，原子替换，返回 diff 和新哈希。哈希检测不能替代任意外部进程的事务锁，应避免同一文件并发写入。支持 UTF-8 中文、CRLF、长文件和连续编辑；非 UTF-8 明确拒绝且保留原字节。 |
| IN1.7 | `shell_exec` 使用 Linux `/bin/sh`，cwd 限于 `/workspace`，支持搜索、脚本和测试。shell/Python/skill 执行显示进度与增量输出，保存退出码、超时和截断状态。 |

“重新生成”复用该轮已有工具回执，仅重新组织回答；不会重新运行写入或脚本。若要重新执行操作，请另发一条明确指令。编辑用户消息会重跑修改后的请求，后续历史会被重写；已发生的文件修改不会随聊天版本切换回滚。

通用文件工具受路径保护；执行进程在非 root 容器内，根文件系统只读，工作区、临时目录和包目录可写，有 CPU/内存/PID 限制，不挂载宿主项目、密钥或 Docker socket。字符串策略只是补充限制，不能视作 Python/shell 的安全沙箱。容器允许网络访问，`pip_install` 仍可安装依赖；包安装/转换不是本期的流式长任务管理能力。

首期不提供宿主机 CMD/PowerShell、Bash 保证、交互式 PTY、跨重启进程恢复或 `SKILL.md` 方法型技能包。共享本地记忆沿用 Ollama 路径；云端使用会话历史和压缩，不自动把本地共享记忆升级为云端记忆。

## 3. 密钥、数据与调用额度

- 用户输入的密钥保存在 `data/private/model-keys.json`；该目录被 Git 忽略，也不在执行容器的工作区挂载中。环境变量 `DASHSCOPE_API_KEY` 仍可替代文件配置。
- 普通启动默认不授权云端读取工具结果，可通过顶部模型设置显式开启。IN1 启动脚本为隔离测试工作区提供默认授权；界面保存的同工作区授权状态优先于启动默认值，因此用户关闭后重启不会再次自动开启。请只放允许发送给云端的材料。
- 工具可返回 `model_observation` 与 `local_result` / `local_attachments`。模型历史取递归投影，完整本地结果供 UI 展示；后续摘要和跨会话工具也不能回读 UI 原始附件。
- 本轮真实模型联调上限 **30 次**，按 HTTP 请求尝试计数，工具后的再次推理和压缩也计数；失败尝试不返还额度。账本为 `data/in1-model-calls.sqlite`，重启不会清零。模型设置显示累计数，到限后保留结果并停止新调用。
- 试用入口目前继续保留这条 30 次总上限。人工试聊同样占用剩余次数；如需增加，应先明确新的额度并调整启动配置，不能删除账本绕过限额。

## 5. 人工对话样例

可以直接复制这些请求，继续追问、纠正或换话题，而不是仅逐项执行测试脚本：

1. “今天只想随便聊聊。以后叫这个测试项目青竹，先不用工具。”
2. “在 /workspace 写一个三行 CSV，用 Python 求平均数；把代码和实际结果给我。”
3. “先读刚才的文件，只修改其中一处数值，再读回来确认其他内容没变。”
4. “搜索工作区里的 TODO，列出文件和行号。”
5. “写一个小 Python 函数及测试，运行测试；故意造一个失败，再根据错误修复并重跑。”
6. “运行一个每两秒打印进度的命令。”运行中展开卡片、点停止，再刷新核对已有输出。
7. “查有哪些技能，查看其中一个的参数后调用；不要另写同样的代码。”
8. “把刚才的处理封装成一个无额外依赖的 skill，注册、核验；开新对话再调用它。”
9. “读取一个不存在的文件；如果失败就解释原因，不要编出文件内容。”
10. “先别继续工具任务了。用两句话讲个轻松的小故事。”随后再追问前面的事实。
11. 回答完成后切模型、编辑重发、重新生成、切换版本，再刷新；核对模型来源和工具执行次数。
12. 把 UTF-8 中文文件换成 CRLF、多处重复文本或 GBK，检查精确编辑冲突/编码提示是否清楚。

记录时分别评价：工具是否真的执行、Web 是否显示正确、输出是否流畅、回答是否可靠自然。失败请保留会话与具体请求，便于回放修复。

## 7. 思考输出与云端工具开关（2026-09-06）

顶部“模型设置”新增两个独立开关，顶栏同步显示工具和思考状态：

- **思考输出**：当前 Qwen 可开启/关闭，按模型保存，下条消息生效。请求供应商返回思考内容，已有可折叠思考过程负责展示；不支持配置的模型会禁用开关并显示说明，仍展示模型实际返回的思考。
- **允许云端使用当前工作区工具**：开启前显示宿主机工作区路径和出站说明。授权包含工具调用、文件读取结果发送给云端，以及按任务执行代码或修改文件；适用于该路径下所有会话及云端模型。它不是只读权限模式，用户要求只读时模型仍需遵守该范围。
- 保存到被 Git 忽略、未挂载到执行工作区的 `data/private/model-settings.json`。不同工作区路径独立授权，刷新和重启后保留。思考开关不会改变工具授权，关闭工具不会撤回此前发送的内容。
- 正在生成时后端拒绝修改，避免半轮切换能力。停止/完成后可以修改，从下一条消息生效；不会自动重发任务或额外扣费。开启后回到原对话发送“请继续实际执行刚才的任务”即可。
- 工具未授权时，系统明确要求模型说明尚未执行并询问是否在设置中开启，不得把代码示例当作已完成任务。用户在聊天中说“同意”不会绕过开关。思考关闭仅在用户明确要求开启时提示设置，不打断普通聊天。
- 相关修复：思考后直接调用工具、没有正文的中间消息也会保存，刷新后思考不会丢失。
