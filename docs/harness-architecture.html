02 · 接口与贡献点

契约／入口何时需要现有能力与限制
CapabilityDescriptor／plugin.json每个 Plugin 必须稳定 ID、API 1、版本、必需／可选依赖、权限与贡献；目录展示不执行代码。
SkillCatalog／SkillSession标准 Skill 自动使用目录发现、导入、校验、版本固定、启停、差异、回退；正文至少含 name、description。
ToolProvider／ToolTransport提供工具时输入 schema、调用与真实回执；执行上下文由宿主绑定，参数不能覆盖模型、会话或授权。
Lifecycle有可启停工具或服务时ACTIVE → DRAINING → INACTIVE；失败留 START_FAILED／STOP_FAILED，依赖按保存意图恢复。
ModelGateway插件需要模型生成时复用冻结会话模型、授权和原账本；稳定请求 ID，UNKNOWN 不自动重发。旧历史兼容入口不升级重发。
TaskProvider后台或长任务时查询、观察、允许操作、取消及恢复描述；事实归插件，不另建宿主任务事实库。
ArtifactProvider／UIContribution提供成果分页或专属 UI 时保存正文通用回退；复杂 TSX 与成果适配器构建登记。历史修订保留范围由提供者决定。
commands／CallPolicy／TurnPolicy命令或业务编排确有需要时命令参数 schema；所属工具规则／阶段说明／历史投影；单编排者冲突在激活前提示。
本版不支持不应据此增加另一套平台在线市场、远程 JS 热加载、任意热替换、通用流程编辑器、多 Agent 平台、任意 schema 自动生成设置页。

历史目标设计与编码原则（展开参考）

以下为 2026-10-21 目标设计存档，其中施工状态与严格验收阈值属于历史；当前实现以本页上方表格及新版验收口径为准。

01 / 核心决策

你的补充成立，两处表述需要收紧

依赖隔离

关闭任意可选能力，不破坏无依赖能力

普通聊天和工作区属于基础系统；搜索是可选插件。关闭金融后，聊天、工作区和已启用搜索完整可用。关闭搜索后，聊天和工作区仍可用，依赖搜索的功能明确显示缺失，不能伪装可用。

“关闭任意能力，搜索仍工作”与“搜索可关闭”存在冲突。验收应按声明的依赖关系判断，而非要求所有功能无条件存活。

扩展稳定性

安装 Plugin 不等于修改 Harness 源码

符合现有 API 的插件，只需安装、校验、登记和激活；可以更新部署清单或加载资源，不改 Agent 循环。只有新插件需要尚未存在的扩展点，才升级宿主 API，并保留明确的兼容版本。

否则“每加插件都更新宿主逻辑”会重新形成业务侵入。可选重启与源码修改是两个不同概念。

模型自主调用的完整路径：发现能力摘要 → 按需读取技能 / 工具 schema → 校验依赖与授权 → 执行 → 返回通用回执。接入后具备被选择的条件；是否选对仍需真实任务评测，不能仅凭注册成功判定。

03 / 两种能力范式

轻量 Skill 即插即用，完整 Plugin 自带业务边界

SKILL / 内容与方法

目录即分发单元

skills/my-skill/
  SKILL.md
  scripts/
  references/
  templates/
  • 复制目录后自动扫描并展示能力摘要；非法格式只隔离该包并显示诊断。
  • 标准文件名为 SKILL.md；兼容导入 skill.md 时由导入器规范化并拒绝大小写冲突。
  • 新增、编辑或删除目录，影响后续运行；当前运行固定原版本。
  • 纯说明不增加进程；脚本走已有受限 Runner，声明并检查运行环境依赖。
  • 复制脚本不触发自动执行、安装依赖或权限提升。
PLUGIN / 可安装能力组件

清单 + 代码 + 可选业务服务

plugins/finance/
  plugin.yaml
  adapter/
  tools/ + skills/
  ui/
  schemas/ + migrations/
  • 声明 API 版本、工具、任务提供者、界面贡献及依赖。
  • 可包含 Skill；Skill 通过能力 ID 依赖插件，不导入其内部实现。
  • 数据迁移由数据所有者负责；股票事实仍由股票仓库维护。
  • 可同进程或外部服务运行，按环境与隔离需要选择。
  • 未知权限或不兼容 API 导致该插件不可激活，宿主仍正常工作。
用户仍可统一看到“能力”或“技能”。内部明确区分 Skill、Tool、Task 和 Plugin。模型只能通过宿主授予的工具执行脚本，不能把 Skill 正文当成绕过权限的依据。
变更接入动作是否改宿主源码
添加方法 / 模板 Skill复制、校验、索引、激活否
添加带脚本 Skill以上动作 + 环境与依赖检查已有 Runner 支持时不需要
添加符合 API 的 Plugin安装、依赖检查、资源登记、激活；必要时重启否
Plugin 需要新扩展机制设计通用扩展点、升级 API、验证兼容性需要，但不加入业务特判
关闭 / 卸载 Plugin停止新调用、收尾、回收注册项；保留业务数据否
04 / 最小公开契约

统一接线，不统一所有业务实现

以下为拟定契约；优先实现搜索和金融实际需要的部分。跨语言边界以 JSON Schema / OpenAPI 描述，Python 与 TypeScript 类型由同一契约生成或校验。

契约宿主统一保证扩展自己负责
Capability / SkillCatalog稳定 ID、版本、摘要、依赖、按需加载、同名冲突诊断描述触发条件、方法正文和资源
ToolProvider输入 schema、可信执行上下文、授权检查、调用回执参数业务校验与实际操作；声明副作用、超时及重试特性
ModelGateway复用会话冻结模型、参数、调用 ID、用量与终态提交已授权材料；业务核验不得交给模型文本代替
TaskProvider统一查询、观察、允许操作与任务归属队列、内部步骤、检查点、具体恢复策略；宿主不再维护第二份任务事实
ArtifactProvider类型、引用、修订号、可见范围、通用阅读回退成果正文、业务报告与专属渲染器
UIContribution命令、设置、面板、阅读器插槽与主题令牌按需加载的受信任组件；不直接访问宿主私有状态
调用与上下文贡献清单声明工具角色和研究排除项；CallPolicy 解释交接规则与实际受理回执，贡献阶段说明；ReceiptPresentation 提供确定性展示；HistoryProjection 整理已授权历史宿主按真实工具所有者选择贡献，工具展示与实际调用共享边界；保留授权、执行和账本，规则版本进入检查点兼容信息；内部展开的 Skill 步骤同样固定资源版本
插件提示贡献清单声明包内文本和适用工具；随部署加载、参与检查点兼容指纹业务使用规则归插件；系统提示权限仅授予明确安装信任的包，不能由普通 Skill 摘要扩大授权
Lifecycle / ResourceScope依赖顺序、健康核验、停止新调用、按所有者释放资源明确启动与收尾协议；持久业务副作用不宣称可自动回滚

Plugin 清单示意

id: finance
version: 1.0.0
harness_api: "^1.0"
contributes:
  tools: ./tools/catalog.json
  skills: ./skills
  tasks: finance.tasks
  ui: ./ui/manifest.json
dependencies:
  required: [model.generate]
  optional: [web.search]
feature_requires:
  online_research: [web.search]
permissions:
  requested: [model.invoke, finance.state]

示意格式，不冒充现有标准。声明不等于授予；宿主校验权限。金融只在适配层连接既有股票服务。

每轮执行冻结的上下文

ExecutionContext
  conversation_id / workspace_id
  run_id / call_id
  model_snapshot
  capability_versions
  granted_permissions
  evidence_scope
  cancellation / deadline

宿主创建，模型参数不可覆盖。跨进程调用须认证并核验上下文。密钥不放进模型可见清单。

数据驱动的是能力目录、配置、状态与 UI 贡献；复杂算法仍是可测试代码。任务状态、回执确定性、成果完整度分别表达。
模型如何自主找到新能力？

会话获得经授权过滤的能力摘要目录。目录较大时提供统一 discover 接口；模型选中能力后读取完整 SKILL.md 或工具 schema。执行结果带明确状态、数据 / 成果引用及错误类别。发现与调用不需要在 Agent 循环增加 finance、search 等分支。

为同一能力保留正例、反例和依赖缺失用例，检验模型能否选对、是否错误触发、失败后能否准确说明。自动发现解决接入，评测检验实际可用性。

05 / 可控的自主更新

模型可以维护 Skill，更新先形成候选版本

可以支持你说的自主迭代：云端模型在用户已授权的能力目录中创建、修改和移除 Skill，经同一工作区工具与更新服务完成。这里定义的是更新机制，不预设某个 Loop Agent 产品的实现。

创建 / 修改候选→格式与依赖校验→脚本测试 / 行为样例→原子激活新版本→新运行使用

权限不扩大

已授权范围内可自动完成更新。不因技能写着“安装”“发布”就得到新权限；新增网络、凭据、本机执行或数据迁移权限须另行授权。

运行不漂移

当前运行引用内容哈希和版本快照。删除先从发现目录停用；正在使用的版本保留到引用释放。下一轮才切换，失败保留旧版可用。

回滚有边界

代码与技能内容可回退；已发生的外部写入不自动撤销。Plugin 的数据库迁移必须有兼容与恢复方案，不能把换回代码称为数据回滚。

Plugin 也能由模型协助开发，但不在本轮运行里直接替换宿主或已执行插件。按现有契约构建、测试、安装并择机激活；第一版不做任意运行中热替换，不让模型修改权限裁决逻辑。
06 / 简洁之道

按职责拆分，限制依赖方向，而非机械切短文件

local-ai-agent/
  harness/
    contracts/        # 稳定接口与数据类型
    runtime/          # 循环、运行、调用与上下文
    capabilities/     # 发现、注册与生命周期
    infrastructure/   # SQLite、HTTP、模型适配
  apps/
    api/              # 薄 HTTP / 事件适配
    web/
      shell/          # 会话、工作区、布局
      extensions/     # 插槽与组件加载
      features/       # 通用交互
      ui/             # 设计令牌与基础组件
  plugins/
    websearch/        # 可独立分发
    finance/          # 股票接入包，不复制业务库
  skills/             # 用户可管理的内容包
  scripts/            # 唯一启动器与平台适配
  data/               # 保留既有事实存储

Stock_Agent_Workspace/
  services/           # 股票业务实现
  ...                 # 既有数据、方法、证据

目录为目标示意，可渐进映射现有 core/、bff/。包可独立分发不意味着必须新增仓库，也不意味着一包一进程。

  • 依赖方向：业务适配器依赖 contracts；runtime 不导入任何业务插件。
  • 组合入口薄：只组装模块，不承载研究、工具或 UI 业务判断。
  • 避免 God files：Agent 循环只处理统一事件和调用；API 按资源拆路由；页面按功能拆状态与组件。
  • 没有万能 Context：按职责提供窄接口，禁止跨模块改写 _tools 等内部字段。
  • 显式调用优先：命令用请求—响应；事件用于观察，不把全部逻辑塞进隐式总线。
  • 边界检查自动化：检查禁止导入、契约兼容、重复 ID、资源泄漏与生命周期失败。
  • 体积分类计量：宿主、插件、镜像、模型、数据分别记录；未启用插件不启动服务。
必须保留的现有资产

唯一启动与退出、现有 conversations.db / model-calls.sqlite / workspace、股票状态与证据、云读授权、冻结模型、UNKNOWN 隔离、账户确认、工作区容器隔离均继续有效。运行轨迹和通用事件可扩展原存储，不另造平行事实库。旧模型 / Dify 任务继续只读，不在迁移过程中恢复或重发。

07 / 迁移路径与完成标准

每一步都通过同一个产品入口验收

01 · 固定契约与边界

从现有搜索、金融提取最小接口；保留兼容适配器，先建立依赖检查与代表性回归样例。

02 · 跑通 Skill 装卸

复制、发现、按需读取、脚本执行、更新、删除与版本固定；验证云端模型在授权目录中的维护。

03 · 抽出搜索 Plugin

替换搜索专属注册和开关接线，贯通工具、配置、服务与界面贡献；验证关闭后的降级。

04 · 统一 Task / Artifact

任务由原所有者持有，宿主投影与观察；成果采用引用和渲染器，不再按 stock 前缀写分支。

05 · 迁移金融侵入

迁出股票上下文、计算口径、来源核验与专属 UI；通过通用 ModelGateway 保持模型继承。

06 · 无关能力反证

接入文档整理等能力；若需要修改 Agent 循环，返回修订契约。再移除旧接线，不保留双通路。

验收场景必须观察到的结果
A · 能力可关闭关闭金融 / 普通 Skill 后，聊天、工作区及已启用搜索正常；关闭搜索后，无关功能正常，依赖项明确降级。
B · 能力可扩展新增合约内 Skill / Plugin 不修改 Agent 循环；模型在正反例任务中正确发现、选择、调用或拒绝。
C · 结构可维护通用运行时无业务导入；无跨模块私有字段修改；单个功能变更集中在所属模块，避免仅按行数拆文件。
D · 更新可追溯编辑不改变在途版本；非法新版本不覆盖旧版；删除不破坏历史；回滚明确区分代码与数据。
E · 故障可隔离插件崩溃、超时、依赖缺失、收尾失败有明确状态；普通聊天继续可用，失败不冒充成功。
F · 退出可确认统一入口停止新运行，等待回执 / 检查点，再停服务与容器；收尾未确认则保留具体错误。
G · 性能可计量记录冷启动、空闲内存、首屏资源、工具延迟和上下文体积；先测现状再设阈值，不以“插件化”宣称性能改善。
最终设计准则：能力以公开契约接入；业务在自己的边界内完整实现；宿主只负责通用机制。先迁通搜索与金融，再以多个全新、有实际用途的能力检验泛化；不引入全量工作流平台、微前端平台或插件市场。
08 / 新能力真实任务验收

用普通人的问题，检验新接入能力能否真正工作

实现完成后的验收必须新建多个有实际意义的 Plugin 和 Skill，不能只把原金融、搜索换目录，也不能用返回固定文本的样例插件代替。建议至少 2 个新 Plugin + 3 个新 Skill，覆盖纯方法、脚本、持久数据、长任务和跨能力组合。下列候选用于规划，具体材料在实现阶段准备。

新增能力候选自然提问示例实际成果检查
资料索引 Plugin“上次那份讲电池回收的材料在哪？帮我找一下，顺便说说主要讲了什么。”命中真实文件、引用可打开、摘要对应原文；跨会话持久索引遵守工作区范围。
批量文档处理 Plugin“这一批扫描件帮我变成能搜文字的 PDF，放到新文件夹里，原件留着。”产出可搜索文件；任务进度与失败项准确，重开页面可继续观察，原件未改写。
会议整理 Skill · 纯方法“这段会开得有点乱，帮我理一下最后定了什么，谁接着做。”决定、负责人、待办忠于材料；没说清的责任人不编造。
表格核对 Skill · 带脚本“这两张表总数怎么对不上？帮我找出差在哪几行。”脚本实际运行，差额与异常行可复核；区分重复项、缺失项和口径差异。
资料对比 Skill · 组合能力“把我们存的那几份方案对比一下，再看看最近有没有变化。”组合资料索引与搜索；区分本地旧资料和网上新信息，缺少能力时明确说明。

提问不泄露解法

  • 不在问题里写插件 ID、Skill 名称、API 或工具参数。
  • 不要求模型“先 discover，再调用某工具”；测试的是自主选择。
  • 保留口语、追问、信息不完整和合理歧义；该澄清时能澄清。
  • 包含不需要扩展的普通聊天，避免凡事都强行调用能力。
  • 使用未参与调试的留出问题及自然改写，防止针对题目硬编码。

分开判定工程与任务成功

  • 契约：注册、版本、依赖、权限、启停、取消、卸载无侵入。
  • 选择：该用时使用、无关时不误触发、依赖缺失时不假装执行。
  • 结果：文件、数据、引用与任务回执真实可核验；不能只看回答流畅。
  • 效率：记录无效调用、额外澄清、延迟、token 与人工接管。
  • 修复后使用留出题复测；已暴露的题作为回归，不再当独立成功证据。

同一组能力还应经历删除、更新、名称相近的竞争能力、脚本报错、服务离线和运行中停用。每个关键场景做多次独立运行，保存模型与能力版本、输入材料指纹、实际轨迹和成果；各受支持模型分别记录，不用一个模型的通过替代另一个。

硬门槛：新增能力不得修改通用 Agent 循环；不得越权、破坏原数据或虚报成果。任务完成率、选择准确性及体验阈值在测试前按场景约定，并报告样本量与失败实例；一次成功、注册成功或工程测试通过都不等于整体验收。
09 / 后续扩展方式

保留少量接缝，不先造一个万能平台

Skill 与 Plugin 是内容组织及分发范式；Connector、Workflow、Agent、Trigger 等更多描述运行方式或贡献类型。它们不必各自成为第三、第四套安装、权限和生命周期系统。

扩展形态如何容纳当前取舍
Connector / 外部工具服务Plugin 提供 Tool / Resource 适配器；HTTP、MCP 等传输藏在适配层。现在保证接口不绑定进程与传输；有具体接入需求时实现对应协议，不预装全套连接器。
Workflow / 持久任务Plugin 实现 TaskProvider，内部可用普通代码、状态机或任务图。现在支持长任务契约；不做通用可视化流程编辑器或新的流程语言。
Agent / 专业委派简单角色作为版本化提示配置；真正独立执行通过受控子运行或 TaskProvider。预留运行父子关联与独立权限范围；有真实场景后实现委派，不先建多 Agent 调度平台。
Trigger / 定时或事件触发只负责提交与用户操作相同的运行命令；身份、授权和上下文要求不变。需要时增加触发适配器；首版沿用“服务运行期间调度”，不新增后台常驻与第二入口。
Resource / 数据与知识源返回带来源、修订号、范围的资源引用，内容由所有者持有并经授权读取。在现有 Evidence / Artifact 引用中明确区分输入材料与输出成果；出现第二个真实数据源后再提取独立接口。
Model / Renderer / Policy分别接入模型网关、UI 贡献与宿主可信策略。使用现有扩展点；普通业务 Plugin 不能替换宿主权限裁决。
现在要做：版本化契约、稳定 ID、明确所有者、能力发现、结构化回执、独立适配器和兼容性检查。现在不做：任意类型动态执行、无限 hooks、通用 DSL、通用总线编排和插件市场。未知类型给出明确“不支持”，以后通过新 API 版本接入。

允许少量有命名空间的展示元数据，但影响权限或执行的字段必须有明确 schema，不使用万能 payload 绕过类型检查。只有两个以上真实实现暴露出共同需求，再提炼新的公共接口；新增接口应能解释它消除了哪一类重复或耦合。

10 / 最终编码原则清单

以可理解、可替换、可验证为标准，按项目需要取舍

适用于本次重构及后续 Skill / Plugin 接入。必须表示架构或正确性底线；优先表示默认选择，可因具体需求采用更简单的实现。原则不用于追求文件数量、抽象层数、覆盖率或单测数量。

原则 / 强度本项目的编码要求避免机械套用
01 · 数据驱动
优先		能力目录、依赖、工具 schema、设置、UI 贡献与明确的状态转换由结构化数据描述；在接入边界校验并版本化。界面从后端快照与事件派生。不把复杂业务算法塞进 YAML；不为消除几个条件分支发明 DSL。配置承载差异，代码承载行为。
02 · 高内聚、无 God files
必须		按变化原因和业务职责组织模块。Agent 循环只编排通用执行；路由只做协议适配；插件管理只负责注册与生命周期。组件状态与相关行为就近组织。文件行数只作审查信号，不设机械上限；不把一个清晰流程切成大量跳转文件，也不制造巨型 utils、Context 或管理器。
03 · 依赖方向明确
必须		插件依赖公开契约，通用运行时不依赖具体插件。数据与资源有唯一所有者；禁止跨模块修改私有字段、复制事实库或形成循环依赖。不为每个具体类创建接口；只在变化边界、跨进程边界或确有替换需求处引入抽象。
04 · SOLID 按需落实
优先		单一职责按变化原因划分；合约内新增能力通过扩展完成；替代实现遵守同一行为语义；调用方只依赖必要接口；业务实现通过组合入口接线。不为了 SOLID 增加层层继承、万能基类或依赖注入容器。函数、模块、Protocol 和组合均可表达这些原则。
05 · 边界校验集中
必须		不可信输入在入口解析为明确类型；内部使用已建立的不变量。跨进程、持久化加载及实际副作用处仍核验身份、当前权限与资源版本，防止状态变化后使用旧授权。减少同一信任域内重复的 None / 类型 / 字段存在检查；不以“入口已验”为由删除执行时授权和并发版本校验。
06 · 条件分支保持清楚
优先		必要的 guard clause 用于非法输入和清晰早退。相同规则集中到所属策略或状态转换中，主流程保留直线叙述。不按 guard 数量评判质量。大量重复早退应修正模型或职责，不改成深层嵌套，也不把简单判断包装成规则引擎。
07 · 函数式思维
优先		转换、归一化、策略判定与状态派生优先写成显式输入输出的纯函数；I/O、持久化和模型调用放在边界。执行快照只读，状态修改集中。生命周期对象可以有状态；不强制 Monad、全局不可变库或反复复制大证据对象。大型内容用版本化引用传递。
08 · 错误与副作用显式
必须		保留有语义的错误类别、可操作原因与调用 ID；失败、取消、结果未知分别表达。重试由幂等性与结果确定性决定，资源随所有者收尾。不使用吞掉异常的万能兜底、静默默认值或自动切换模型掩盖失败；不用 try/except 包住每一行。
09 · 测试以功能为中心
优先		主要投入公开契约、模块集成和用户可见功能场景，检查真实状态与成果。真实模型的自然语言任务另作验收，记录非确定性与失败样本。不为每个小函数、getter、转发层补单测；不按实现调用顺序或内部 mock 次数锁死重构。功能测试不等于全部改为昂贵浏览器 E2E。
10 · 关键规则保留小测试
必须		金额与数值口径、权限、状态转换、幂等、UNKNOWN、版本兼容与数据迁移，采用聚焦且有区分力的测试；适合时用参数化或属性测试覆盖边界。减少低价值测试不等于删除可靠性保障。旧测试只有在重复、失效或已有等价行为覆盖时才合并移除，不按数量清理。
11 · 抽象由真实需求推动
优先		先写清楚具体实现；稳定跨边界契约可以先定义，其余在真实重复出现时提炼。容许暂时的小量重复，避免业务差异被错误合并。不提前建设通用平台、无限 hooks 或任意 payload；已有两个实现也不自动意味着必须抽象。
12 · 性能与依赖有证据
必须		按需加载能力与前端资源，控制传入模型的工具和资料体积；测量后再优化。新增依赖说明必要性、体积与生命周期成本。不把“纯函数”“插件化”直接当作高性能证明；不为了少一层调用破坏职责边界，也不为理论扩展预装庞大运行时。

推荐的测试投入顺序

  1. 契约与功能集成：Skill 装卸、Plugin 启停、任务恢复、成果读取、模型继承。
  2. 少量关键入口 E2E：同一 Web 入口的提交、观察、刷新、退出与重启。
  3. 高风险规则的小范围测试：数值、权限、幂等、迁移与未知回执。
  4. 独立真实模型验收：自然提问、能力选择、跨能力组合与实际交付。

离线集成测试可在外部模型 / 网络边界使用可控替身，内部核心链路尽量真实。外部提供者另做连接验证；不把离线测试结果等同于真实模型质量。

每个改动的简短审查问题

  • 规则是否放在唯一负责它的模块里？
  • 是否又让通用循环认识了某个具体业务？
  • 能否直接读懂主流程、状态与副作用？
  • 新增校验是否跨越了新的信任或状态边界？
  • 测试能否发现用户可见问题，而非只复述代码？
  • 新抽象和依赖是否有当前需求支撑？

局部风格取舍可以说明理由；既有入口、数据、授权与回执规则不能因代码精简被削弱。

落地要求：以这份清单指导实现，不做一轮纯命名或纯拆文件的“大扫除”。每批围绕一个可验证功能边界完成迁移，保持用户可见行为、数据与运行语义连续。
11 / 设计依据

借鉴机制，不照搬产品体量

本方案基于双仓库静态审阅及前轮核验的一手资料。Cordis 借鉴生命周期与组合；VS Code 借鉴界面贡献点；OpenCode 借鉴服务端运行状态；Pi 借鉴核心与扩展分层。新增验收、编码原则与扩展取舍属于本项目设计要求，当前不绑定新的大型框架。
