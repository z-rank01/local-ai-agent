# 股票能力接入与开发顺序

> 决策日期：2026-09-06。状态：用户已授权实施，IN1 工程交付与验证见 [IN1运行与验证](./IN1运行与验证.md)；IN1.H 等待人工验收。两个仓库都直接在 `main` 开发，不创建额外分支或 worktree。

## 1. 目标与阅读方式

先提供自然、连续的大模型对话，需要时再调用通用工具或股票工作流。普通聊天不进入股票业务流程；业务规则在实际工具执行时校验。本地运行 harness 不要求总控只能使用本地模型。

不等待旧功能规划全部完成，也不一次搬入完整股票系统。顺序为：最小可靠聊天底座 → 三类股票只读能力 → 一条研究任务闭环 → 扩展专业能力并逐项替换 Dify 依赖。

- 本文件：本仓库的实现步骤、模块归属和验收要求。
- 股票仓库 `docs/local-ai-agent接入.md`：后台复用、适配契约、业务边界和迁移顺序；[本机链接](D:/Stock_Agent_Workspace/docs/local-ai-agent接入.md)。
- 股票仓库 `docs/计划.md`：接入任务 `IN0`～`IN4` 的唯一进度表，包括本仓库任务、证据和提交；[本机链接](D:/Stock_Agent_Workspace/docs/计划.md)。本文件不另维护完成复选框。
- [旧部署记录](../本地AI-Agents部署流程.md)：现有功能与历史交付，不能据此认定新接入已完成。

跨仓库链接中的本机路径仅便于查阅；实现不得硬编码这些路径。

## 2. 现有基础与具体缺口

以下来自 2026-09-06 静态代码检查，不代表已执行新一轮真实聊天验收。

| 模块 | 已有基础 | 本次需要补齐 |
| --- | --- | --- |
| `apps/web`、`bff` | 流式聊天、会话管理、编辑重发、回复版本、文件与工具卡片 | 停止和异常状态一致；中途结果与最终回答分别展示；本地附件独立交付 |
| `core/llm_client.py`、`core/runtime.py` | Ollama `/api/chat` 调用 | 先接一个用户确定的目标供应商和模型；完整适配认证、流式事件、工具调用与错误；保留 Ollama |
| `core/agent.py` | 模型自主选择工具，多轮读取结果后回答 | 默认六轮耗尽后的收尾；工具调用元数据；异常、中断与已有结果保留 |
| `bff/service.py`、`core/conversation_store.py` | SQLite 历史与结构化工具结果 | 持久化完整 assistant 工具调用及对应结果，重建历史时保持顺序和关联；旧会话兼容处理 |
| `core/context_manager.py`、`core/memory_manager.py` | 历史压缩与记忆基础 | 压缩不切断工具调用与结果；刷新、编辑、重生成、摘要后的连续语义和数据边界 |
| `core/tool_registry.py`、`core/tool_router.py` | YAML 工具描述和 HTTP 分派 | 新后端地址注册、认证、可信身份、请求编号和结果转换；不能只放 YAML 就视为接通股票后端 |
| Web 模型选择、`bff/service.py`、`core/runtime.py` | 界面已有模型选择控件，后台仍使用固定 Ollama 客户端 | 选中的供应商与模型实际用于本轮推理，回复记录实际模型；保留已配置 Ollama 的选择路径 |
| `skills/runner`、`config/tools/skill_*.yaml`、`code_exec.yaml` | 临时 Python 执行、技能查询、运行与注册已有后端实现 | 核对工具可见性并接通发现、调用和创建复用链；默认 `TOOL_TIER=core`，技能运行/注册属于 `extended`，存在代码不等于模型能调用 |
| `gateway/prompts/modules` | 模块化提示词 | 移除工具后强制“执行步骤／结果／说明”模板；普通聊天自然表达，业务规则交给工具 |

云端接入前必须检查文件预取、工具结果、历史重放、摘要和记忆更新等所有模型输入通路。现有本地文件可读权限不自动等于允许向云端发送正文。模型选型和凭据通过后续本机配置落实，不在文档中记录密钥，也不把当前 Ollama 接口误写成已支持任意云端供应商。

## 3. 分阶段实现

### IN1：最小可靠聊天底座

依赖：用户查阅文档并指示开始实施；落实首个目标模型及可用配置。

1. `IN1.1`：先接一个目标云端供应商/模型并保留 Ollama，Web 列出已配置、已验证可用的模型；选择结果经 BFF 路由到实际推理客户端，回复记录实际供应商/模型，不能只改变显示标签。验证普通流式回复、工具调用及模型不可用时的明确错误，不静默换成其他模型。通用接口允许以后扩展，任意供应商添加、全量模型自动发现和完整管理平台后置。
2. `IN1.2`：统一模型消息、工具调用、工具结果与 UI 事件的对应关系；完整落库并正确重放，保留调用参数、标识和执行状态，兼容现有数据库。
3. `IN1.3`：修复达到调用上限、模型失败、工具失败、断流和停止生成的收尾。工具失败作为可理解的结果交回模型；模型不可用时由界面明确说明，保留已取得内容，不伪装成功。
4. `IN1.4`：调整自然对话提示词，验证上下文压缩、历史和记忆；为云端输入建立显式数据边界。完整本地附件不进入后续历史、摘要或自动记忆的云端输入。
5. `IN1.5`：保留模型自主选择现成工具、临时编写并执行 Python、发现和调用已注册 skill，以及按用户需求创建可复用 skill 的能力。接通 `skill_list`/`skill_info` → `skill_run` 和编写 → `skill_register` → 再次调用的链路，核对 `core`/`extended` 工具分层；模型可见目录与实际可用工具一致，不仅在提示词中声明有技能。沿用现有 runner、执行范围和资源限制，工具结果返回模型供其检查、纠错和继续回答；完整技能管理 UI 后置。
6. `IN1.6`：新增精确编辑能力（工具名称实施时冻结），支持匹配原文后局部替换、冲突/多处匹配检测、返回差异并重新读取核验；文件变化时不盲目覆盖。覆盖中文、换行与编码、长文件局部修改和连续两次修改。
7. `IN1.7`：补齐容器内最小命令执行闭环。明确实际 shell、工作目录、可用程序、超时、退出码和输出截断，支持目录/文本搜索、脚本执行和测试；按执行环境落实工作范围，不只修改提示词或简单删除字符串黑名单。当前执行器是 `/bin/sh`，若选择 Bash 必须安装并明确配置，不冒充 Windows CMD/PowerShell。提供运行状态、增量输出/进度与最终回执，停止或超时后核实进程及子进程状态；首期不做交互式终端和跨重启进程恢复。
8. `IN1.H`：按[IN1 Web 与工具验收案例](./IN1验收案例.md)执行“读 → 改 → 跑 → 检查 → 再改”及多轮体验，用户在 Web 选择已配置模型后自由连续聊天。工具轨迹、输出流、结果事实和自然回答分别验收；未达标先修底座，不扩大股票接入。此阶段可持续使用通用能力，不需要等待 IN2 股票工具。

验证路径：普通聊天 → 用现有工具计算或读合成文件 → 追问 → 纠正 → 换话题 → 回到原话题 → 刷新后接续。另覆盖工具失败、调用上限、编辑重发和停止。定向自动检查用于验证协议、持久化和异常边界，不以通过数量代替自然体验。

IN1 必须额外覆盖以下可观察结果，功能完成状态仍只在统一计划中记录：

| 验收场景 | 通过标准 |
| --- | --- |
| Web 选择目标云端模型或已配置 Ollama 模型 | 实际请求与选择一致；会话/回复保留真实模型信息，刷新可恢复；切换后的新一轮使用新选择，旧回复来源不被改写 |
| 编辑重发或重新生成 | 明确使用的模型，界面与实际请求一致；请求参数不能被固定运行时忽略 |
| 自主完成临时计算 | 用户只表达目标，模型按需要选择 `code_exec`、生成 Python、读取实际结果并解释；代码报错可据回执修正，不虚构运行成功 |
| 发现并调用已有 skill | 合成测试技能可被 `skill_list`/`skill_info` 发现，模型按需调用 `skill_run`，结果进入本轮和后续对话 |
| 保存为可复用 skill | 用户要求“把这个方法保存下来，下次还用”后，模型生成含 `SKILL_METADATA` 和 `run(params)` 的脚本并注册；后续新对话能发现并复用，无需重复粘贴代码 |
| 工具分层或服务不可用 | 配置允许的技能工具实际出现在模型目录；未开放、缺依赖、执行失败等情况有真实回执，不把不可调用工具描述为已执行 |

技能相关测试使用合成文件和测试技能，不操作日常账本。股票专业工作流后续作为同一工具体系的扩展，通用分析和临时 Python 能力继续保留。

完整场景及记录要求集中在[IN1 验收案例](./IN1验收案例.md)，包含模型选择、文件操作、Python、精确编辑、shell、skills、历史、故障和自然长对话。案例是待执行要求，不是测试通过记录。

### IN2：三类股票只读能力

依赖：`IN1.H` 通过。先以独立测试账户、合成报告和可核验状态联调，研究 worker 关闭，不启动研究或修改日常账本。

1. `IN2.1`：与股票后台明确工具契约。先仅开放查看账户、查找已有研究、读取研究报告三类能力。**已冻结（2026-09-07）**：`stock_account_view`（查看账户）、`stock_research_find`（查找已有研究）、`stock_report_read`（读取研究报告）；身份归属、幂等、来源时间、模型观察与本地附件字段、错误映射及可插拔要求见股票仓库 `docs/工具网关.md` 的"IN2：local-ai-agent 只读接入契约"小节（对应提交 `684f804`）。select 会话标的指针本期不纳入；旧 Dify 会话任务在新入口不可见为接受现状。
2. `IN2.2`：增加股票适配模块和工具注册。BFF 注入身份、会话与请求标识；模型只提供业务参数。现有网关使用的票据、序号和安全引用由适配层管理。**已实现（2026-09-07）**：`core/stock_bridge.py` 按轮管理 prepare/step/finish（票据、序号、request_id 不出适配层），`config/tools/stock_*.yaml` 三个工具在未配置 `STOCK_BRIDGE_URL` 时不注册；模型只见白名单投影，F01 完整报告在轮末经 `tool.local_result` 事件回填工具行、Markdown 渲染且不进历史。配置方式见 `.env.example`；隔离联调（不启动 worker、独立 state 目录、零模型调用）验证了真实网关握手、账户投影、空查找、非法引用引导与附件收割。模型在环验收留待 IN2.3/H 与新预算。
3. `IN2.3`：模型读取授权事实与摘要，UI 直接展示完整本地报告；后续追问仍遵守相同边界。研究价格包含证据时间，账面成本不当作市值。**已实现（2026-09-07）**：股票工具卡片含任务/裁决/数据状态徽章与证据时间，账户卡提示"账面成本非市值"；泄漏验证以离线测试固化（跨轮历史、上下文压缩、跨会话工具均不含本地报告正文）；合成验收环境为股票仓库 `scripts/seed_bridge_demo.py`（幂等，合成任务带 `SYNTHETIC_DEMO_NOT_FOR_CLOUD` 标记供人工核验边界）。
4. `IN2.H`：用户自由完成“看账户 → 找报告 → 解释报告 → 纠正股票 → 换话题 → 返回报告”；验证对象和来源一致，不暗中创建任务。

只把旧 `/api/master/broker/run` 包装成一个“回答股票问题”工具不能算完成此阶段。新总控应直接选择具体股票工具，避免把旧模型循环和回答格式整体嵌套回来。

### IN3：一条完整研究任务链

依赖：`IN2.H` 通过。复用股票后台队列、预算、幂等和检查点，不在本仓库新建第二套研究调度器。

1. `IN3.1`：接提交、查询、停止、恢复及结果读取，使用服务端可信任务引用；刷新和重试不重复创建任务。**已实现（2026-09-08）**：新增 `stock_research_submit`/`stock_research_cancel`/`stock_research_resume` 三个工具（契约见股票仓库工具网关 IN3 小节），桥接在 step 无观察时改用其脱敏 tool capsule 作为受理回执（QUEUED/CREATED/REUSED 对模型可见）。
2. `IN3.2`：长任务排队后立即返回受理状态，让聊天继续。持久化任务与会话关联，完成结果可在后续对话或界面刷新时取得；状态通知不冒充已经读过报告。**已实现**：submit 入队即返回受理回执；进度/结果经 stock_research_find（含 unread）与 stock_report_read 在后续轮次取得；工具描述写明受理≠完成。
3. `IN3.3`：区分“停止生成”和“停止研究”。断开聊天流不自动取消研究；研究取消由独立工具请求指定任务，已发出模型调用的停止语义以后台实际能力为准。**已实现**：Web 停止按钮只断聊天流；研究取消仅经 stock_research_cancel（异步请求停止语义）；恢复走 stock_research_resume（服务端校验证据/版本/检查点，失败或结果不明的付费调用不重发）。

**IN3 隔离联调证据（2026-09-08，带 worker 的隔离后台，零 Qwen 调用）**：submit 600519 → QUEUED/CREATED → worker 真实执行（真实日线数据，技术 SUCCEEDED + 业务 HOLD/NEEDS_MATERIALS 未耗模型调用）；同标的重复提交被 reuse 未新建；find 显示 SUCCEEDED+unread；report_read 返回投影+F01 附件；resume 请求入队后被 worker 以“不适用局部续跑”明确拒绝；对已完成任务 cancel 返回友好说明。运行中任务的中途取消未实测（任务结束太快），该语义由股票侧既有回归覆盖。注意：带 worker 启动隔离后台会自动执行其日常管线（日监控 catchup + scan + 自动研究），属系统设计行为。
4. `IN3.H`：验证提交一次、跨轮查询、结果读取、失败说明、定向停止与检查点恢复。独立任务并行不混淆标的；有前置依赖的专业步骤保留顺序。

先做离线/隔离联调，再按后续明确的模型调用预算进行真实验证；文档计划不是运行日常任务的授权。

### IN4：扩展专业能力与移除 Dify 依赖

依赖：首条研究链人工验收通过。按实际使用反馈接入其他职责和人工操作入口。

总控先独立于 Dify 对话入口，专业研究过渡期仍可调用后台 Dify 工作流。之后逐项替换专业模型适配器，保持输入材料、独立角色、输出契约、检查点和前置回执一致。启动器、操作入口和历史访问迁移单独验收；停用旧服务、删除应用和数据均不随代码接入自动发生。

## 4. 模块归属与延期项

| 归属 | 内容 |
| --- | --- |
| 本仓库通用核心 | 模型适配、消息协议、工具执行循环、上下文与记忆、聊天 UI、通用工具结果展示 |
| 本仓库股票扩展 | 股票工具描述、后台连接配置、身份与请求绑定、股票结果卡片；使用独立模块，具体新目录在实施时确定 |
| 股票仓库 | 数据采集、量化、专业角色和工作流、研究队列、账本、策略规则、人工门禁、可信业务回执 |

专业角色每次只加载选定职责的提示词、材料和必要证据，不共享整段总控历史；共享模型供应商不等于共享角色记忆。股票账本事实不由通用聊天摘要代替，通用文件/代码工具不能成为绕过股票执行门禁的写入通道。

更多主题、更多供应商、多用户、复杂插件市场、统一调度平台等暂不作为接入前置。旧规划中已有功能继续保留，只有影响当前验收的缺口优先修复。

宿主机 Windows PowerShell/CMD、交互式 PTY/长期后台进程，以及基于 `SKILL.md` 方法说明的技能包列为后续扩展，均不作为 IN1 前置。本期保留 Python 可执行 skills；以后可与方法型 skills 共存。Linux 容器工作区与 Windows 本机路径必须明确区分。

## 5. main 开发与记录约定

- 两仓库直接使用 `main`，不创建股票专用分支。每批开始检查已有改动；与其他 AI 协作时按文件和批次协调，不覆盖其工作。
