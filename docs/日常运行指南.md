# 日常运行指南

| 镜像内插件 | 操作与边界 |
| --- | --- |
| 资料索引 | 工作台“能力清单与工具登记”启用；激活先核对文件服务中的版本和资源哈希，失败按唯一入口 `-Build` 重建。支持 Markdown、UTF-8 文本、可提取文本的 PDF；扫描件须先 OCR |
| 缓存与来源 | 索引保存在所属工作区 `.capabilities/document-index/`；原件不改写。检索会核对源文件哈希，过期结果不作为当前资料返回，须重新索引 |
| 停用收尾 | 通用生命周期先拒绝新调用，等待已接收调用结束；收尾失败保留具体状态，不能显示已成功停止 |
| 一次性恢复 | 补跑不保存下次开机自动领取任务的意图；完成/阻断暂停，仍由原页面人工确认 |

| Skill 版本（重构施工） | 说明 |
| --- | --- |
| 方法包更新 | 新 Runner 中正式运行开始时保存内容版本，`skill_info` 返回版本正文和资源目录；修改原 `skills/` 目录供后续运行重新检查 |
| 保存位置 | 派生版本在原工作区 `.skill_registry/versions/`，不是另一份会话库；不要手工改写，已保存检查点可能引用旧版本 |
| 能力管理 | 工作台提供目录导入、检查更新、启停、待激活版本及回退；导入只复制已挂载工作区中的包，不执行代码或安装依赖。移出能力目录保留原文件和历史版本 |
| 权限变化 | 新增权限或依赖不自动激活；宿主不支持或未授权时保留具体原因。旧式 Python Skill 仍走兼容通路 |
| 状态迁移 | 原会话库升级 v10，先备份 `.before-v10.sqlite`；不以还原旧库回退代码，避免丢失新消息 |
| 当前边界 | 新源码须唯一入口 `-Build` 及 BFF 重启后生效，在线状态见股票仓库计划；完整 Plugin 迁移仍施工中 |

“补跑 / 重试恢复”仅核对历史恢复记录，保留只读研究范围；完成或阻断后自动暂停。检查具体结果后才使用原账户确认操作，不为补跑关闭只读限制。

## 选择模型

| 操作 | 行为 |
| --- | --- |
| 顶部选择模型 | 立即保存到当前会话；切换、重开时恢复该会话选择，不改变其他会话 |
| 尚未创建会话 | 选择作为本次新会话待选值，创建时保存；未指定时使用安装默认值 |
| 同会话多页面 | 定期同步已保存选择；旧页面提交不一致模型时返回配置冲突，刷新选择后再发起 |
| 运行中切换 | 只影响下一项运行；当前分析、核对、后台子任务和兼容检查点继续使用原快照 |
| 股票后台 | 显示“跟随本会话模型”；无所属会话先选择会话。旧模型/Dify任务只读，不启动或恢复 |
| 本地辅助 | 主模型按需调用 local_agent，固定本地Gemma4:26b。执行轨迹和回执显示实际模型；不联网、不发布、不递归，不自动回退或下载模型 |
| 不可用/权限撤销 | 返回具体错误；不会静默替换供应商。UNKNOWN保留且不自动重发 |

公司研究续行表是历史通路说明；旧模型任务现统一只读。当前实现和实测范围见[会话模型统一记录](./记录/2026-10-21-会话模型统一与本地委派.md)。

## 查看与控制运行

| 操作 | 行为 |
| --- | --- |
| 顶栏“运行中／已暂停” | 打开全部工作区任务列表，查看模型、步骤、耗时、结果及HTML是否发布；脚本通过聊天API发起的运行也在这里 |

| 多页与关页 | 只按实际页面连接计数；刷新重连有宽限。最后页面关闭约15秒开始保存回执、停股票与容器，再退出；脚本流不为页面保活 |

## 离线后恢复

| 步骤 | 页面操作 | 注意 |
| --- | --- | --- |
| 1 | 开启股票技能，查看业务模式、已核对日期及“恢复与待办” | 先识别缺口与阻塞 |
| 2 | 按提示补跑或重试恢复，观察逐日记录 | 失败先处理原因；暂停或重启后可续未完成步骤 |
| 3 | 核对恢复摘要及待办；在“人工操作”输入“帮助”“账户”或“权益待办” | 历史补采不等于离线期间实时监控 |
| 4 | 点“核对并恢复运行”，阅读提示，再点“确认恢复” | 暂不执行日常任务时先暂停；新订单仍需逐笔确认 |

历史数据缺失、权益疑点或模型结果不明时，按界面原因核查，不手动改数据库状态绕过阻塞。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 目录配置待生效 | 确认 Docker 正常运行，在工作台点“检查并应用目录配置”；控制器不可用时退出后经启动.bat 重启。失败保留有效配置，不换成其他目录 |
| 页面提示重新通过启动.bat打开 | 唯一启动器负责页面凭据；请再次双击启动.bat，同一浏览器刷新会保留会话和草稿。不要把 data/private 的凭据文件复制到工作区 |
| 镜像重建等待较久 | 查看 data/logs/tool-containers.log；首次依赖下载可能较慢，仍使用同一启动器 -Build |
| 本机目录写入被拒绝 | 系统限制聊天进程直接写入时使用该工作区文件容器；容器不可用返回 503，先恢复 Docker 并用启动器 -Build 重建 |
| 浏览器未自动打开 | 手动打开 `http://127.0.0.1:9510`；若仍不可用，查看 `data/logs/daily-bff.err.log` |
| 9510 已占用 | 检查旧页面与服务；从旧页面退出或关闭后等约 15 秒再启动 |
| 股票技能启动失败 | 页面把固定启动请求交给**启动器控制器**执行；控制器不可用时，页面会保存开启意图并提示重新双击启动.bat。启动失败看 data/logs/stock-service.err.log 与 data/logs/service-controller.err.log |
| 股票日志报 `unable to open database file` 或 `readonly database` | 先清 WAL 锁文件：退出整个栈后删掉状态目录的 `state.sqlite-shm` 与 `state.sqlite-wal`（**不要碰 `state.sqlite`**），再重新启动 |
| 股票任务未推进 | 检查“高级管理”的任务暂停状态、业务模式和恢复待办 |
| 联网搜索启动/关闭失败 | 检查启动器第 3 步的本机服务控制器与 Docker；控制器日志在 `data/logs/service-controller.err.log`；首次拉取镜像可能需要等待 |
| 关闭页面后仍运行 | 确认其他标签页是否仍打开；约15秒是开始收尾的宽限。查看任务列表的收尾错误；有错误不强杀，处理后重试“退出”。检查 `AUTO_EXIT_ON_CLOSE` 是否为 `false` |
| 启动器窗口被关掉（聊天仍能用） | 容器开关与退出时的停容器都会失效（聊天后端够不到 Docker 命名管道，只能请启动器代做）。重新双击 `启动.bat` 恢复控制器，再通过页面退出收尾全部工作区容器 |
| 新字段/新行为不生效 | 多半是进程没换代码：`config/tools/*.yaml`、`core/**`、`bff/**` 改了要**重启聊天后端**；`config/prompts/**` 同样。容器不改代码，只换 YAML 时不需要重建 |
| 工具参数像是被忽略 | 改过 `skills/**`（容器内代码）却没重建镜像：用 `.\scripts\start-daily.ps1 -Build`。自查最快：`Invoke-RestMethod http://127.0.0.1:9101/openapi.json` 看该工具的请求字段是否含新参数 |
| 页面是旧界面 | 改过 `apps/web/**` 后要 `npm run build --prefix apps/web`，再刷新页面（Ctrl+F5） |

改代码后各自怎么生效，见仓库根目录 `AGENTS.md` 的「改完代码后怎么让它生效」。

更多操作细节与原始说明见[历史原稿](./记录/日常运行指南-原稿.md)。

## 桌面缓存位置说明（2026-10-14）

桌面窗口沿原唯一入口启动。浏览器运行缓存保存在 `data/private/desktop-webview/`，不提交 Git；会话仍在原 `data/conversations.db`。旧根目录 `tmp*` 不能盲删，先核对内容并正常关闭占用窗口。关闭窗口与退出行为不变。

## 固定端口启动排错（2026-10-15）

| 情况 | 行为与处理 |
| --- | --- |
| 未占用但禁止绑定 | 启动前实际试绑 9510/9511；失败立即停止，尚未启动容器或后台。用 `netsh interface ipv4 show excludedportrange protocol=tcp` 查看 Windows 排除范围，不改项目端口 |
| 已有监听 | 保留原身份检查和重复启动复用；端口有人监听不等于本项目服务 |
| 后端初始化后退出 | 立即提示退出码及 `data/logs/daily-bff.err.log`，不继续等待全部就绪轮次 |
| Windows 动态保留覆盖固定端口 | 本机已经管理员操作恢复 WinNat，并将 9510–9511 设置为持久管理保留；普通进程绑定与完整启动均通过。其他机器不可直接删除未知排除范围；网络服务重启会影响 Docker/WSL，须用户确认 |
| 再次故障 | 保留错误信息；不要循环重启或删除数据库。持久保留不能避免其他程序监听或防火墙限制，按实际错误处理 |

实现与实测见 [固定端口恢复记录](./记录/2026-10-15-固定端口启动恢复.md)。

## 简报交付到对话

在目标对话打开工作区，选择已保存的HTML简报，点击“发送到当前对话”。消息中的“阅读简报”直接打开沉浸阅读器，刷新后仍可使用；相同版本重复点击不重复发消息。文件交付不调用模型，明确区别于自动生成；版本文件请保留，不覆盖旧稿。生成回复已附工作区HTML链接时，可直接从回复阅读，无需重复交付。

内部股票读取材料不再自动生成用户阅读卡；已收到的材料保存在原研究记录，并按会话所属工作区归档到 `reports/_research/`。文件只代表已收到页，不代表全文或完整研究。切换界面工作区不会迁移原会话材料；用户HTML简报通过显式交付消息阅读。


### 可选插件环境与回退边界

插件环境准备与运行分开，仍由 `启动.bat` 的启动器负责 Docker。服务标识、容器资源和工作区映射由登记清单及原会话数据库生成；BFF 不运行 Docker，不允许页面传入命令、镜像名或挂载目录。可选容器不随普通聊天容器默认启动。

回退到不认识插件容器的旧启动器之前，先用当前版本的页面“退出”完成全部 profile 的收尾，再切换代码；不能让旧入口只停止普通容器而遗留插件任务。保留原会话库、插件绑定和新写入成果，不用恢复旧数据备份丢弃新内容。当前具体插件是否已具备完整页面操作与验收，仍以股票仓库 docs/计划.md 为准。
