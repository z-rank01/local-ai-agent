# 放宽输出限制与发布门槛（2026-10-21）

本批来自只读诊断：云端模型（qwen3.5-flash / deepseek-flash）在自然提问后很难产出简报正文与 `report.html`。诊断为**发布门的收敛性**问题，而非模型能力问题，因此改动集中在限制模型"能看到什么、能写多长、能不能发出去"的三层。安全与数据完整性不变量未改。

## 判断依据

实测事实（只读，未改数据）：

| 观察 | 数值 |
| --- | --- |
| 已记录研究会话 | 45 个，其中 `PUBLISHED` 22（有 `report.html`）= **49%** |
| 发布尝试 | 62 次；`publication-attempts/rejected-*.json` 16 个 |
| 运行事件中的拒绝原因 | 单独核对阻断 28、引文不在原文 14、计算值未在引句定位 14、单位不匹配 3、待回读 8、输出截断 **0** |
| 单个失败会话的痕迹 | 34 个 `drafts/*.md`（51–1261 B）、11 轮核对、4 次发布被拒 |
| 45 个会话对应的主题 | 约 4 个（万德斯、格力、农机、美的+海尔）——每次失败都新开会话 |

由此定位到三条限制，按影响排序：① 发布门由"每次都给结论、每条都能阻止"的独立核对把守，改稿补读又使核对指纹失效，形成不收敛的循环；② 工具结果被按工具截断（file_read/web_fetch 8000、code_exec 6000 字符），模型只看得到原文开头；③ 研究模式用正向白名单，读方法前只开放 5 个工具。

## 具体改动

| 已定位问题 | 改动 | 边界 |
| --- | --- | --- |
| 工具结果被截断，模型看不到完整原文 | `TOOL_RESULT_MAX_CHARS`（默认 0 = 不截断）；仍要截断时把完整结果写到 `data/private/tool-results/` 并在消息里给出路径 | 路径仍在工作区内，可 file_read 分页读回；不改工具容器的返回 |
| 轮次、预算、时间窗压住长研究 | `AGENT_MAX_ROUNDS` 默认 0（不限）；`WEB_SEARCH_BUDGET`/`WEB_FETCH_BUDGET` 默认 0；`STOCK_WINDOW_SECONDS` 可配且 0 = 不设截止；`COMPACT_THRESHOLD` 0.6→0.9 | 研究模式本就绕过轮次上限；停滞守卫（连续无新证据）保留，用于收尾而非中断 |
| prefetch 预算 0 等于不注入 | 0 = 不限，另加 `PREFETCH_ENABLED` 显式关闭 | 不改"一次最多 3 个文件"的注入范围 |
| 未声明上下文窗口的模型被压到 32k | `model_capacity` 不再 `min(CONTEXT_WINDOW, 32768)`，按配置回退 | 声明了窗口的模型仍以目录为准 |
| 核对每条意见都能阻止发布 | 默认 `PUBLISH_REVIEW_ENFORCE=false`：核对照常执行并保存，但不阻断；为 true 时只有 `severity=blocking` 阻断，且证据新增不再直接使核对失效 | 核对记录、候选稿、答复仍逐份保存；`UNKNOWN` 仍不自动重发 |
| 发布契约接近编译器级：图表必须画、引文必须含字面单位、加减单位必须一致、草稿不能混用内联字段 | `charts` 可空；删掉图表单位的字面正则与 `calculation:` 的单位相等要求；混合加减单位允许；`draft_path` 可与内联字段混用（内联优先）；分页读失败退回整文件读 | **引文与数字仍须能在实际收到的原文中定位**（`PUBLISH_QUOTE_CHECK`，默认开）；计算结果仍须与算式一致 |
| 研究模式把工具面砍掉大半 | 正向白名单改为**负向屏蔽**（删除、改名、装依赖、注册技能、跨会话读取共 10 个）；`tool_names` 从注册表推导 | 破坏性操作仍被 `tool_router.dispatch` 同一名单拦截 |
| 研究入口以"股票技能可用"为前提，而 `.env` 未配 `STOCK_BRIDGE_URL` | `06_tools.txt` 改为 research_begin 可用即生效；新增 `08_research.txt` 定义触发条件与正文结构 | 不新增启动路径，不改股票业务规则 |
| 工具 schema 占 ~13k token | 默认用 `short_description`；精简两个最长的工具描述，细则移入提示词模块 | 参数 schema 与必填项未改 |
| `data/tmp` 测试残留 | 清理 215 个目录 / 2224 MB | 目录本身保留（`test_research_progress` 用它作临时基址） |
| `agent.py` 里两个只定义未调用的辅助函数 | 删除 `_format_tool_params` / `_parse_tool_args` | 仅删死代码 |

提交：`19c70cf`（输出限制）、`1a5d75f`（发布门槛）、`2b5d73c`（工具面）及本记录的配套提交。

## 遗留

- `agent.py` 的 `run()` 仍有 700 余行，未拆分；`_review_candidate`（92 行）与发布分支仍耦合在 agent 内。
- `core/` 仍有 39 处裸 `except Exception`；`stock_*` 17 个模块（约 2,400 行，11 个不足 100 行）未合并；92 个测试文件未按域整理。
- `qwen3.8-max` 未声明 `context_window`（现按配置回退）；`max_tokens` 只在模型目录或 `MODEL_MAX_OUTPUT_TOKENS` 显式给出时才发送——未核实的上限会换来 400 硬失败，比截断更糟，故未预填。
- 线上验收未做：需用唯一入口起服务后，用同一自然问题连跑 3 次，确认 3/3 生成 `report.html` 且 `publication-attempts` 的拒绝数下降。

## 边界

放宽的是"模型输出与发布"这一层：截断、轮次、预算、图表要求、核对阻断。未改：工作区路径隔离、模型密钥、容器生命周期、账本、`UNKNOWN` 不自动重发、审计落盘。引文物证校验（默认开）保留，因为它是防止报告引用不存在原句的根；如需完全放开，显式设 `PUBLISH_QUOTE_CHECK=false`。
