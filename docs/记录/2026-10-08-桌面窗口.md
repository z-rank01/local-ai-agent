# 2026-10-08 桌面窗口（pywebview）

## 做了什么

为同一入口增加桌面窗口展示形态：`启动.bat -Desktop`（或 `start-daily.ps1 -Desktop`）用 pywebview（Edge WebView2）窗口承载 `http://127.0.0.1:9510` 页面，代替打开浏览器标签页。

## 关键设计

- **后端零改动**：桌面窗口里跑的是同一个页面，心跳/SSE keepalive 照常；关闭窗口 = 心跳停止 = 现有 auto-exit 约 15 秒走 `_request_stack_shutdown`（股票优雅收尾 → 停 docker → 杀进程）。页面内"退出"按钮同样可用。
- **不是第二条启动路径**：入口仍是 `启动.bat`，`-Desktop` 只是第 7 步的展示分支；不带参数行为与之前完全一致。
- **回退**：桌面窗口进程启动失败时自动回退打开浏览器。
- **与股票施工无交集**：未触碰 `bff/app.py`、`core/auto_exit.py`、stock_service、docker 链条与前端任何文件。

## 安装与运行排坑（本机实测 2026-10-08）

| 坑 | 现象 | 处置 |
| --- | --- | --- |
| pypi.org 不可达 | pip 默认源挂死十几分钟 | 用镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple`，加 `--disable-pip-version-check --no-input` |
| pip 缓存目录权限 | 构建 proxy_tools 时 `WinError 5 拒绝访问`（`~/AppData/Local/pip/cache`） | 加 `--no-cache-dir` |
| pythonnet netfx 初始化被拒 | `Failed to resolve Python.Runtime.Loader.Initialize`（本机 .NET Framework 4.8.1 在，但 CAS 沙箱拦了程序集加载；Unblock-File 无效） | 在 `.conda/python.exe.config` 启用 `loadFromRemoteSources`；`start-daily.ps1 -Desktop` 分支会在缺失时自愈写入（.conda 已 gitignore） |
| coreclr 备用路线 | 配了 runtimeconfig 后卡在 `System.Windows.Forms.ContextMenu` TypeLoadException（.NET 8 已删该类型，pythonnet 反射翻车） | 弃用 coreclr，走 netfx；不留 runtimeconfig 文件 |
