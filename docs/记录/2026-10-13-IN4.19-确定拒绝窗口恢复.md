# IN4.19：确定拒绝窗口恢复

| 范围 | 约定 |
| --- | --- |
| 用户条件 | 用户确认农机HTTP400源于忘记充值，已经充值并授权继续；原供应商回执缺错误码，不补写原因 |
| 恢复对象 | 只恢复原农机C01唯一确定供应商拒绝窗口；原任务、原失败、成功窗口和UNKNOWN保留 |
| 入口与数据 | 正式会话原恢复工具→现有股票只读工作进程；独立验收目录、同一会话库和模型账本；无新启动器或数据库 |
| 尝试关联 | 原请求、输入指纹、失败调用、实际参数与执行指纹核验后建立稳定恢复子请求；重复请求或改写说法复用同一次尝试 |
| 旧版本 | 仅C01/C02的5a1aa旧发布版本按完整原来源清单、逐文件批准及冻结提示词核验；实际运行版本另记，不全局放行旧任务 |
| 本批交付 | 先恢复单个阅读窗口，交付仍为PARTIAL；全文综合、C02及公司材料组织另需接续，不宣称整条研究完成 |

## 工程与离线验收

| 场景 | 结果 | 限定 |
| --- | --- | --- |
| 确定拒绝 | 原FAILED、known_failure=true、unfinished=false及HTTP拒绝必须一致；原模型、参数、方法及材料核验 | 不能把用户充值说明改写成供应商原回执 |
| 去重/UNKNOWN | 新尝试成功后重复恢复不再调用；新尝试UNKNOWN后换说法也复用同一未知尝试；原成功、活跃、截断和UNKNOWN不可取得新恢复ID | 26项专项通过；实际未知请求不主动制造 |
| 暂停 | 步骤边界让出保存稳定子请求，模型未调用 | 离线通过，线上待真实触发 |
| 来源兼容 | 原冻结版本完整清单指纹重建；真实C01出站材料与原版本函数生成完全相同；当前提示词逐字一致 | 后续任何未批准代码/策略/提示词变化阻断恢复 |
| 正式路由 | 同会话安全引用恢复主题；能力询问、假设和先不执行不会创建任务 | 首轮测试复现“了解恢复能力”误入，已修复；26专项最终通过 |
| 工作进程范围 | 原worker_start动作可选job_ids，仅配合research_only=true；只领取指定只读任务，重启保留范围，主动改模式可清除 | 不改账户规则；防止本次验收领取其他旧任务 |
| 必要回归 | 67项主题/阅读/运行器回归；补修后50项恢复/质量生命周期/N2回归通过；专项最终26项通过 | 不把重叠测试相加；非本轮线上触发路径仍待实测 |
