## 大材料读取故障恢复

| 项目 | 实际处理 |
| --- | --- |
| 原因 | 2700条原文位置展开时，每个字段重复遍历全部内部标识，正则缓存反复失效；broker读取仍在写事务内，引起超过25秒的读取超时和SQLite锁错误 |
| 修复 | 内部映射在每份文档只编译一次，长ID优先，URL目的地原样保留；正文、阶段、来源及原始快照不删减 |
| 验证 | 真实材料候选约3秒生成（正文1页、参考179页）；实际源码42项针对性检查通过，在线读取待加载复核 |
| 安全边界 | 供应商账本首窗口COMPLETE/stop；股票线程因持锁退出且未保存有效正文。唯一退出接口返回409后，核验仅本次验收PID及无供应商RUNNING，才应急停止该故障进程 |
| 孤立回执 | 取得原工作进程独占锁并备份同一状态库后，仅把本批孤立窗口标UNKNOWN，记录供应商COMPLETE元数据与原因；不把缺失正文记成成功，不自动重发原请求 |
| 继续方式 | 原任务ID、材料和分窗哈希不变，恢复同一任务的其他独立窗口；首窗口缺口保留，不新建ID绕过UNKNOWN |
| 版本 | 仅展示修复；专业执行bundle完全不变，已有队列及检查点保持原冻结要求 |
| 未宣告通过 | 首窗口成功保存与C03成功节点重启去重仍待真正触发；失败样例及异常记录保留，不能据供应商完成宣称内容通过 |
| 剩余边界 | 写事务内生成展示的耦合仍存在，本次避免已复现的逐标识重复扫描；更大规模的无锁展示拆分需独立兼容设计，不能擅改已冻结任务版本 |
