# 模型目录瞬时失败保留

| 项目 | 实现与验收 |
| --- | --- |
| 复现问题 | 模型目录每30秒刷新；刷新失败时只保留静态条目，曾发现并成功调用的模型被移除，后续同模型研究可能在出站前被拒绝 |
| 修复 | 仅在探测失败时，保留同供应商、同地址、同密钥选择器下已发现的确切模型，标记RETAINED_AFTER_PROBE_FAILURE；不换模型，不换后端，不重发UNKNOWN |
| 明确移除 | 目录成功返回空列表或不再包含模型时，仍以新目录为准；供应商地址改变时不把旧模型复制到新地址 |
| 无效响应 | 模型目录缺少合法data列表时属于探测失败，不误作成功的空目录 |
| 验收 | 模型目录及研究接口56项通过；首次沙箱运行受SSL加载失败影响，已在正常宿主环境重跑通过 |
| 与v9关系 | v9的后7窗仅留INTERNAL_REQUEST_REJECTED_422；离线完整材料重建均通过公开材料校验。目录瞬时失败是已复现的独立缺陷，不能据此断言已证明旧422的具体原因；股票侧新增固定拒绝分类以便后续核对 |
| 部署 | 待唯一入口重载；本记录不表示原任务已恢复或公司研究已通过 |
| 冷启动复验 | startup33页面首次查询出现“所选模型未配置或名称不唯一”，消息仍在输入框、未发模型。进程内保留不足以覆盖冷启动；已将本轮明确指定且真实调用验证过的qwen3.8-flash加入既有models.json，仍用原供应商与密钥管理，不改默认模型 |
