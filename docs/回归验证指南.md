# 回归验证指南

> 更新：2026-09-14。本文件合并聊天与工具案例、连续对话样例、股票服务恢复回归。测试设计与历史通过结果分别记录。IN1.H 已于 2026-09-07 由用户经验性验收通过（见股票仓库[计划](D:/Stock_Agent_Workspace/docs/计划.md)），但 44 个必测案例矩阵与第二段 12 轮对话**未逐条全量执行**；本批工程与浏览器抽样结果见 [运行与验证记录](./历史/开发与验收记录-2026-09.md)。功能范围见[接入步骤](./股票能力接入.md)，阶段完成状态和执行批次统一记录到股票仓库计划。本文件中的示例不表示功能已实现或测试已通过。

## 1. 如何执行和判定

先验证工具协议与故障边界，再从真实 Web 界面发起任务，最后由用户自由连续使用。每个必测案例均观察下方四个维度，不能只从 API 调用成功推断体验合格。示例允许改写、换数据和换顺序，不要求模型选择固定工具序列；专门测试某工具时才明确指定它。

| 维度 | 观察要求 |
| --- | --- |
| 执行正确 | 对照实际文件、退出码、计算结果和模型请求；失败不能标成功，重复点击/重试不能产生意外重复操作 |
| Web 轨迹完整 | 工具开始、运行、完成/失败可见；名称、参数摘要、耗时和结果可展开；重试能区分，文件链接可打开，刷新后结果仍可查，不显示秘密参数 |
| 输出顺畅 | 首个状态和正文及时出现，较长任务期间有增量输出或真实进度；文本不丢失、重复、乱序，不永久转圈；工具输出与最终回答分区清楚，停止后状态一致 |
| 回答可靠自然 | 结论来自实际结果，区分已执行和计划、部分成功和全部完成；能解释和追问，不照抄内部错误码或强制模板；纠错成功后不把过时故障堆到最终回答中 |

记录提交到首个状态、首个正文/工具输出、最大无更新间隔及总耗时；区分模型等待、工具运行和 UI 延迟，按目标模型/机器建立体验基线。不能虚构进度，也不要求工具尚未返回时提前给出最终答案。短命令允许一次返回，长命令不能只有无期限静态转圈。

## 2. 测试材料与隔离

在实施验收时建立独立会话库、测试技能目录与 `/workspace/in1-acceptance/`，不清空用户已有 workspace，不操作股票日常服务或账本。以下文件由测试准备步骤创建，不要求用户手工制作；本次文档提交不创建它们。

| 文件/材料 | 内容及独立核对基准 |
| --- | --- |
| `sales.csv` | 列为 `region,amount`，四行为 `华东,100`、`华东,200`、`华南,50`、`华南,150`；合计 500，均值 125，华东 300、华南 200 |
| `sales_missing.csv` | 在上述数据追加 `华东,`；明确缺失值策略后计算，不能自行把空值当真实零收入 |
| `calc.py` | 一个把 `[1,2,3]` 的均值错误地除以 2 的合成脚本；正确结果 2，并配有独立断言 |
| `notes.txt` | 中文及空格文件名变体、两处重复短句，另有唯一标题；用于精确编辑、多处匹配与路径验证 |
| `large.txt` | 至少 200 行，每行有行号和独立标记；用于局部编辑、搜索、输出截断与前端长结果 |
| 测试技能 | 一项可发现的词频统计 skill，输入“苹果 香蕉 苹果”时苹果 2、香蕉 1；使用独立测试名称，避免覆盖日常技能 |
| 故障桩与慢脚本 | 可控工具失败、模型流中断、调用上限；慢脚本分段输出编号，记录可核验进程标识及停止状态 |

先用合成资料覆盖确定性结果。联网案例单列为条件案例，网页内容变化不影响本地必测结果。真实模型调用按实施批次约定预算执行；额度不足的案例记“未测”，不记“通过”。

## 4. 连续体验脚本与条件案例

至少完成两段由真实 Web 发起、每段不少于 12 轮的连续对话；不是每轮新会话，也不能用预置历史替代真实轮数。工具步骤数、真实模型调用数和用户轮数分别计数。用户可自由改写以下顺序：

- 连续脚本一：闲聊 → 解释统计概念 → 查测试目录 → 分析表格 → 纠正区域 → 比较缺失策略 → 保存报告 → 打开文件 → 精确改标题 → 换话题 → 回到报告 → 核对证据 → 总结尚未完成事项。
- 连续脚本二：查可用技能 → 调用 → 修改需求 → 编写新技能 → 注册 → 验证 → 运行失败脚本 → 编辑修复 → 再跑断言 → 查看进度 → 停止慢命令 → 继续讨论 → 刷新后回顾；再用新会话复用保存的技能。

| 条件案例 | 启用条件 | 验收重点 |
| --- | --- | --- |
| 联网搜索并引用来源、读取网页后对比 | 搜索与抓取服务已配置 | 搜索/抓取过程可见，链接真实，失败或旧信息明确说明 |
| 从合成 Excel/PDF 提取内容并计算 | 对应解析依赖可用 | 提取来源和计算对应，不能将解析失败当空文件 |
| 安装测试技能缺失依赖后再运行 | 测试环境允许依赖安装且包已选定 | 安装状态、错误、后续重试可见，依赖来源和实际环境明确 |

条件未满足记“未测/不适用及原因”，不能挪用为必测案例通过证据。Windows 宿主机 PowerShell/CMD、交互式终端和方法型 SKILL.md 包不在本期验收范围。

## 5. 证据、质量判定与复测

每个案例记录：编号、日期、代码提交、模型/供应商、工具目录版本、测试材料、Web 会话/请求标识、预期与实际产物、工具结果、四个维度结论、耗时指标、缺陷及复测结果。截图/录屏和原始回执保存在本机测试证据目录，进度中只引用不含凭据的摘要。区分离线故障注入、真实工具、真实模型和人工验收，不混算成功率。

结论使用“通过、部分通过、失败、未测、不适用”。必测案例均应完成；核心维度仍失败或缺测时 IN1.H 不勾选。UI 展示成功但后端没执行、后端成功但 UI 丢结果、回答自然但事实错误，都不能判为通过。修复后复测受影响案例及至少一条相关连续链，不只重跑最后一句；保留首次失败记录。

最终邀请用户进行不预设工具序列的自由体验，记录是否能自然继续工作。完成这份矩阵是 IN1 的工程和体验验收，不证明任意任务都可靠，也不代替 IN2/IN3 的股票业务验收。

记录时分别评价：**工具是否真的执行、Web 是否显示正确、输出是否流畅、回答是否可靠自然**。失败请保留会话与具体请求，便于回放修复。

## 7. 股票服务与恢复回归（独立现金账户）


先创建一个**全新的独立现金演示账户**，在股票仓库根目录执行：

```powershell
.\.venv-paper\Scripts\python.exe -X utf8 scripts\seed_n2_demo.py --state-dir data/n2-acceptance-01
```

脚本遇到已有数据库会拒绝覆盖。重复验收改用新目录名，不删除或重置旧数据。现金账户没有持仓，因此这段恢复不调用外部数据源或模型。

1. 运行聊天仓库 `scripts/start-daily.ps1`。先保持股票关闭，确认 Web 能正常加载，工具列表中没有股票工具。
2. 在“股票服务”填入上述独立验收设置并保存，开启股票后台。应显示任务执行“已暂停”、业务“恢复核对中”，显示演示脚本生成的缺口（2026-09-14 基线为 **4 个交易日**；其他日期以实际交易日历为准）；股票查看工具出现。
3. 点击“开启任务执行”。恢复记录应从 **0/N → N/N 已完成**，已核对日期推进到最新收盘交易日；此时仍待用户确认。
4. **先点击“暂停任务执行”**，再点击“核对并恢复运行”及“确认恢复”。应变为“正常运行”，任务执行仍暂停。这样不会启动正常日任务或自动候选研究。
5. 展开“逐日恢复记录”，核对缺口中的每个交易日各有一条完成记录；历史信息不完整的说明仍在，不能被描述为过去已监控。
6. 单击“关闭股票后台”，按钮应立即显示“正在关闭股票后台…”，等待后台退出后自动显示“后台未运行”，无需第二次点击或手动刷新；再等待至少 5 秒，状态不应回跳或出现连接失败。Web 保持可用、股票工具消失。再次开启后，已核对日期、逐日恢复记录及 worker 暂停选择应保留，不重复入账。
7. 退出日常 Web/BFF 后再次运行脚本，确认配置和开关选择保留。最终关闭股票后台，再将连接配置切回日常目录 `simulation`；日常库存在真实阻塞时按待办处理，不能套用演示库的通过结果。

研究能力体验属于后续人工验收：日常账户确认可运行并开启 worker 后，提交/查询一项研究，暂停或关闭前观察收尾。此过程可能触发原有日常管线和模型预算；零调用验收不包含该动作。
