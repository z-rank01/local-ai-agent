## 多目录、多会话工作区回归（R2）

所有在线验证仍经根目录启动.bat；使用独立验收会话和专用目录，不另建会话库。

| 场景 | 预期 |
| --- | --- |
| 一个工作区创建两个会话 | 共享目录；消息、模型、方法、草稿与附件独立，刷新后恢复 |
| 搜索只命中正文 | 显示所属工作区及命中摘要，不切换或重载当前会话 |
| C/D 盘两个目录 | 原地上传、预览、下载、重命名、新建目录；无源目录复制 |
| 同工作区及目录重叠 | 409 携带执行会话，不受理冲突消息；不同目录可并行 |
| 运行中删会话、删消息、切版本 | 409；停止或断开后释放执行锁 |
| 新旧工作区隔离 | 文件工具与 Shell/Python 均不可访问未添加目录；默认组遮蔽其他组托管目录 |
| 凭据与网络隔离 | 外来工具凭据返回 403；容器不能无页面凭据读取 BFF 会话；各组网络不同，私密凭据不能出现在公开响应 |
| NTFS junction 与失联 | 文件路径及脚本预检拒绝链接越界；失联根显示不可用、不回退到托管目录，恢复原目录后可用 |
| 目录移除后重新添加 | 稳定目录 ID 恢复；历史链接仍指向同一源目录 |
| 云端授权 | 关闭读取、只读、读写三态；增加目录到已授权工作区需要确认 |
| 配置失败与重启 | 保留有效配置和待生效意图；激活前检查容器 ID/版本；主机目录写入受限通过文件容器 |
| 回收站与脚本 | 各根目录删除恢复、冲突/移除根拒绝；默认主要目录执行及跨根目录读写 |
| 布局与报告 | 六档宽度及 360px，无横向越界；报告卡→文档→阅读器→返回文档；输入法、键盘与 reduced-motion |
| 完整退出 | 股票收尾后停止全部工作区容器组、聊天后端与启动器 |

桌面模式应将 WebView 缓存写入 `data/private/desktop-webview/`，保持私密模式，不在仓库根生成浏览器目录。正常关闭后才能清理旧缓存。来源检查应区分正文讨论术语与明确引句，同时保留标题、加粗标签、后置/并列引句及真实假引句检查；术语不误检不代表内容语义已通过。

## 固定端口启动排错（2026-10-15）

| 情况 | 行为与处理 |
| --- | --- |
| 未占用但禁止绑定 | 启动前实际试绑 9510/9511；失败立即停止，尚未启动容器或后台。用 `netsh interface ipv4 show excludedportrange protocol=tcp` 查看 Windows 排除范围，不改项目端口 |
| 已有监听 | 保留原身份检查和重复启动复用；端口有人监听不等于本项目服务 |
| 后端初始化后退出 | 立即提示退出码及 `data/logs/daily-bff.err.log`，不继续等待全部就绪轮次 |
| Windows 动态保留覆盖固定端口 | 本机已经管理员操作恢复 WinNat，并将 9510–9511 设置为持久管理保留；普通进程绑定与完整启动均通过。其他机器不可直接删除未知排除范围；网络服务重启会影响 Docker/WSL，须用户确认 |
| 再次故障 | 保留错误信息；不要循环重启或删除数据库。持久保留不能避免其他程序监听或防火墙限制，按实际错误处理 |

实现与实测见 [固定端口恢复记录](./记录/2026-10-15-固定端口启动恢复.md)。

### 离线回归的网络边界

使用 `./.conda/python.exe -m tests.run_offline` 运行完整行为回归。该测试驱动禁止 httpx 同步与异步真实 HTTP 传输，保留 MockTransport / ASGITransport；任何真实传输尝试即使被业务代码捕获，也使最终命令失败。它不是应用启动入口，不启动替代服务。测试日志中的供应商 URL 可能来自模拟传输，不能只凭 URL 把测试计为真实模型调用。

真实模型验收仍从唯一启动入口的页面/API 执行，单独保存会话、请求 ID、输出与失败，不混入离线通过率。


可选服务的功能回归包括 tests.test_plugin_services、tests.test_document_batch、tests.test_container_transport 和退出顺序检查。离线 OCR worker 是明确的测试夹具，只证明状态、原件保护、取消、幂等与中断语义，不证明 OCR 效果。真实验收必须从唯一入口准备可选环境，核验容器身份后通过聊天/任务页面处理实际文件，再核对原件哈希、输出 PDF、全文文本和关闭后的资源。


旧式 Skill 回归覆盖：冻结后修改/删除、篡改快照拒绝、宿主版本头不可被模型参数覆盖、停用后零执行、缺失或新增依赖保持待处理；不导入源码、不自动安装。离线执行 `python -m tests.run_offline tests.test_skill_versions tests.test_skill_catalog tests.test_tool_result_delivery tests.test_practical_skills`，真实执行仍由唯一入口加载 Runner 验证。

插件启动与清单回归：tests.test_plugin_startup 覆盖跨执行环境、逆登记顺序依赖、重复依赖只激活一次、缺失依赖隔离及无效清单在目录/启动中的一致拒绝。

本地插件安装回归 tests.test_plugin_import 覆盖目录/ZIP、源包更新、固定版本、修改拒绝、版本差异、信任确认、原 API 鉴权、冷部署/构建确认、回退及卸载后历史保留。真实验收须用原入口重启构建并实际调用新增工具，离线文件复制不替代部署成功。

本地插件冷安装构建失败时，唯一启动器保留 `*.plugin-failed` 日志、恢复原包后重建，不另启执行器。包内资源在导入时校验；恢复与部署的实际验收状态见股票仓库 docs/计划.md。
